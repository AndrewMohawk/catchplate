# Fresh consume completion on the original private continuation

This .216 source path extends the [fresh consume continuation](control-plane-oidc-session-activation-completion-recovery-consume.md)
after its genuine authorization, grant, reservation and one claimed protected
SQL exchange. It is private source integration, not a public recovery action,
token release, current-session confirmation or cookie result. Historical absence
and unsigned SQL output never establish non-execution or authorize SQL retry.

## Actual owner and originals

`control_plane_oidc_session_activation_completion_recovery_consume_completion._complete_on_active(active)`
requires the actual source-owned completion phase and its one-shot latch. The
dispatch input must be the exact sealed dispatch result owned by that same
active context, not a stored record, decoded graph or successful caller DTO.
The independently configured consume completion endpoint and exact
`release_hints` bool select the existing normal or release-hints wire profile.

The helper retains the dispatch's genuine caller/grant controls, eight original
SQL inputs, enrolled current-state authority and original pending scope. It
re-admits the reservation controls, joins the actual pending digest and derives
the expected completion marker and after-vector from those originals. One
completion request carries only the fixed wire purpose and original caller
authorization. Neither the request nor an old token is added to the journal.

One inherited work/window/deadline spans dispatch, completion transport,
retention and verification. Parent continuity invokes the actual still-live
dispatch; the completion child is not fed back into its own ancestor. Original
owner, policy, resources and source-result seals remain checked. Signed expiry
and observed clock bounds can only narrow; no closed actor or old authority is
revived.

## Retain DATA before genuine completion admission

After the sole socket exchange and normal transport return, exact framing is
checked and custody retains completion raw4. The release-hints profile then
retains its raw2 tail, including empty frames for an uncertain response, before
the status or signature branch. Both calls use the actual work and full current
guard directly, not a metrics-stable callback.

The [guarded records path](control-plane-oidc-session-activation-completion-recovery-consume-records.md)
uses the same global consume and SQL slots. Its exact-work latch already pinned
the completion-profile bool before SQL contact. Normal completion ends the latch
after raw4; the hints profile permits exactly one raw2 append and then ends it.
No restart restores the latch, replaces original uncertainty or authorizes a new
SQL attempt. A lost or invalid response is not permission to retry.

For an acknowledged response, the helper independently verifies the returned
signed complete request and state ACK using the originally enrolled root/key.
It joins the expected pending sequence/head, actual complete identity and action,
all original completion-marker fields, and the signed writer observation against
the original marker/after-vector. It then adopts the newly narrowed signed
control lifetime. Unsigned status and hints cannot substitute for these checks.
An uncertain response remains retained DATA; it is not an authenticated commit.

The private sealed `_ConsumeCompletion` retains response originals, optional
hints, after-vector and the genuine current guard. Its access remains tied to
the same live owner and completion phase. This is not an independently reusable
permission or a terminal browser response.

## Preallocation and acceptance boundary

The completion response is capped at **64 KiB before body allocation** for either
wire profile. A fixed **4 MiB** completion reservation includes its **2 MiB**
guarded journal I/O lane, reservation/control captures, before/after vectors,
writer observation, request/framing and bounded response representations. It
adds to the genuine dispatch's reservation inside the pre-reserved **8 MiB**
execution extension, alongside the earlier **32 MiB** preparation lane, within
the unchanged **64 MiB** original-representation ceiling. It creates no fresh
budget and does not claim measured heap/RSS bounds.

The source path supplies no public route, token, cookie or current-auth result.
Public continuation, release authority and full deployment/production acceptance
remain separate. No SQL retry, automatic fallback or original expiry renewal is
introduced. Source only: unbuilt, unexecuted and unprovisioned.
