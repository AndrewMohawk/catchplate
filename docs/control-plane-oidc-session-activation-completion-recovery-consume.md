## Claim, acquire, prepare and export

1. Independent parent configuration supplies the consume-input endpoint, root
   issuer policy and historical activation planner original. Genuine policy
   admission precedes the existing consume-family durable attempt claim.
2. The successful claim precedes the sole input-issuer contact. The client
   tightens the complete raw2 planner/history response to 256 KiB from its
   header lengths, before reading either body. It retains those opaque original
   bytes before genuine request-bound input admission; an uncertain or invalid
   response does not authorize a retry or deletion of the spent claim.
3. The [private planner continuation](control-plane-oidc-session-activation-completion-recovery-consume-planning.md)
   independently re-admits the exact root-issued planner/history pair and their
   original activation provenance. One protected prepare returns raw6; its
   immutable DATA record is published before status, scope and signed-plan
   admission. One export returns raw7, likewise retained before admission and
   exact prepare/export correspondence checks. Ciphertext remains opaque here.
4. The actual `_ConsumeAttempt` yields only within the live private context in
   its prepared phase. Parent and child guards remain separate: descendants use
   only original ancestors, while the parent never calls its own plan child.
   Final plan checks and normal actor cleanup precede closure. Closing clears
   the ephemeral raw16, input material and plan references; a closed owner is
   not a reusable continuation.

All original operation, subject, packet, enrollment and state joins remain
required. Historical activation authentication does not renew expired activation
execution authority. Fresh consume authority is independently configured and
issued; a signed-looking reply, local metadata or a missing record cannot replace
that admission or authorize any later SQL effect.
