# Archived activation target authority

`control_plane_oidc_session_activation_history.py` supplies the actual pre-intent
raw5 and retained-intent target inspectors with a shared, cold-only archive
lifetime and independently selected historical scope. This is target/possession
inspection, not execution, token release or fresh actor permission. It does not
open the private activation ciphertext or construct a successful permission DTO.

## Original-first selection

Parent `activation_history` shares the actual root-admitted registration and
finalization archive. Each historical scope owns genuine original activation
execution/planning, consume execution and release-intent configuration under its
archived root. No retained record can enroll a key or add a scope.

For raw5, bounded original caller configuration/generation/enrollment locators
select a unique already admitted execution scope. The genuine root enrollment,
caller signature and exact signed plan are authenticated before the plan's
planner receipt and original issue time select the final archive snapshot.
That snapshot must select the very same cold scope. Original caller and plan
intervals must fit it. Only then does the actual pre-intent inspector historically
re-admit the unchanged planner bootstrap, reconstruct independent static
expectations and perform genuine caller/plan/target/old-token joins.

This removes the prior ordering that admitted the current planner before loading
the historical originals. The current parent is used only when activation history
is disabled. Enabled history has no current-pin fallback, no ambiguity tolerance
and no rewriting of signed source labels or old bootstrap dates.

Retained intents use a distinct unique configuration/generation/intent-enrollment
locator. The shared resolver re-admits the original root enrollment, intent
signature and every independently configured scope field, then checks the
authenticated original interval against its archived cohort. The retained-intent
consumer separately re-admits finalization ownership, exact target, possession
and still-live delivery expiry. Lookup or a parsed intent is never release
authority; expiry is never renewed.

## Capacity and lifetime

Before finalization or activation body1, the caller reserves the actual measured
sealed parent, upstream held originals, shared historical canonical originals
and their conservative captures, fixed locator/replay headroom and token/key/
subject bookkeeping within the original 64 MiB accounting ceiling. Shared
history byte aliases are counted once by exact identity. The cold helper excludes
parent and upstream additional bytes so its callers can compose them explicitly.

The finalization chain uses its existing combined preflight and genuine ACK
admission. Only afterward may the caller discard its full replay result and keep
the cold-only finalization continuity guard. The next selected pair receives
three eighths of the remaining allowance, preserving eight selected encoded
representations for original replay; its concrete size is checked again before
signature work. Target reservation totals retain the same upstream addition,
parent, archive and selected inventory rather than creating a new allowance.
These are source-known representation bounds, not a Python heap/RSS guarantee;
large valid inventories may fail closed.

All guards retain the original owner, work and clock floors. Archive lifetime
may only narrow the processing window. Selected-scope guards are siblings of
their genuine receiving children, never inserted into their own ancestors.
The actual target `live` guard retains both; ordinary target fields are not
accepted as proof by later actions.

This slice does not complete historical activation/consume execution or the
proof, grant and token-release continuation under old authority. Those consumers
and explicit older-source adapters remain separate H05 work. No SQL retry,
profile fallback, build/runtime validation or production acceptance is claimed.
