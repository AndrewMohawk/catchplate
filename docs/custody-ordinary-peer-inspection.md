# Ordinary C9 services: retained root peer inspection

This is an explicit software-service successor, not native NSM admission or a
new signing role. Old five-service launch/v1, guest launch/v1 and
`--guest-c9-generation` remain unchanged. Runtime remains generation-only v5;
the separate commitment runtime/selector is not admitted by this branch.

The independently installed `/etc/serverware/custody-generation-five.json`
selects closed `serverware.custodyFiveServiceLaunch/v2` (the same eight fields).
`FiveServiceLaunch.start()` then uses the fixed
`--guest-c9-generation-inspected` selector for all five actual parked children.
No environment or release flag can select inspection. `GenerationInputs`
requires the exact non-signing `peer-inspection-policy` credential, verifies
its bytes and eight fields against the actual runtime/role/original deadlines,
and publishes closed guest launch/v2 with the fixed credential name. The C9
signature pins the policy bytes; the policy has no delivery-digest self-pin.
Independent operators still supply/sign the existing exact public originals;
no key, PID, runtime assignment or policy is generated by this change.

## Genuine privilege boundary

The selected entry admits C9, arms its original kernel startup/lifetime timers,
and forks once before threads, secret-key reads or UID drop. The helper closes
all inherited descriptors except its private channel, stop pipe, one admitted
listener, actual service-parent PIDFD and selected public policy original.
It retains root with only DAC_READ_SEARCH and SYS_PTRACE capabilities, no
ambient/inheritable capabilities and no new privileges. It has its own actual
PID/start/boot owner, original absolute BOOTTIME lifetime timer and parent-death
SIGKILL. The service retains the original startup timer until its real
constructed transition; parent failure kills the helper as well. A first
inspection is not interpreted as constructed or as a renewed startup window.

Those capabilities are powerful host privileges, not a read-only sandbox.
The fixed non-signing worker is part of the trusted host boundary; its narrow
protocol is not protection against compromise of the worker itself.

Every bounded request carries exactly the accepted service connection and its
peer PIDFD. The actual service SCM credentials/PIDFD/start must match the
retained parent and final C9 UID/GID. The helper selects only the signed runtime
peer and listener, calls unchanged `from_inherited_direct` and
`revalidate_packet_pidfd`, and holds the first exact socket for its entire
session. The original executable/cgroup/security-label checks remain mandatory;
no executable FD, memory operation, arbitrary PID/path or key capability is
returned. The request/reply is private same-invocation synchronization, never a
portable admission receipt. The client authenticates the real fork helper's
per-packet kernel identity, not the socketpair's pre-fork SO_PEERCRED.

The parent keeps a separate stop/reap guard. After role drop it cannot signal a
root helper, so guard closure wakes the fixed stop pipe and reaps the actual
child by PIDFD under the original lifetime. Parent death/expiry remain kernel
bounds. A malformed packet, changed session, failed measurement, lost reply or
expired original poisons the client; there is no reconnection or host fallback.

## Listener credentials and actual bridge release

Business resources are created/listened by root. Selected Rust entry repeats
`listen(1)` only after actual final UID/GID drop and before accepting a client.
Linux `unix_listen` updates its stored peer credentials on a successful call,
including an already listening socket; this is kernel identity, not relabeling.
See [Linux AF_UNIX implementation](https://raw.githubusercontent.com/torvalds/linux/master/net/unix/af_unix.c).
An already queued connection retains its previous credentials and must fail
existing exact client admission; it is not repaired or retried.

After that real call the child sends distinct `custodyOrdinaryListening/v1`
over its original parent channel. The actual launcher checks exact delivery,
role/invocation, retained PIDFD/start and final SCM UID/GID, and records
`final-role-listening` without disarming startup. Constructed still occurs
later, after the real service handshake/construction.

Use the actual source-owned
`launcher.release_proof_cohort(cohort, release_original=..., transfers=...)`
for this selected bridge path. It joins the genuine parked bridge PID/start and
held executable against all five signed runtime expectations, waits for all
five real listening notices under the unchanged startup bound, then calls the
real `ParkedProofCohort.release` once. It does not wait for constructed first
(which would depend on bridge connection), and never invents final cgroup,
label or IMA facts from parked identities. Native release still independently
checks every assigned purpose/activation and its own original deadlines.

## Source-only boundary

This batch has not been built or executed. Deployment still needs independently
approved full final peer expectations, actual fs-verity executables, C9/key/history
provisioning, required kernel PIDFD/SCM_PIDFD/clone3/close_range support, and a
host permitting the narrow root inspection capabilities/LSM reads. The helper
does not bypass LSM refusal. Ordinary authorities still report TrustedHostNoTee.
No constructed, installation, durability, NSM or pilot-ready claim follows from
the listening notice or from source completion. Retain partial provisioning
evidence; no unlink, repair, restart or fresh deadline is supplied here.
