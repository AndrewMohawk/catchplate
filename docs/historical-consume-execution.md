# Protected planning for historical activation consumption

The `.224` connection carries the signed input bridge into the actual protected
consume planner and recovery caller preparation. Public historical consume
execution remains disabled: grant, reservation, SQL and completion custody
profiles still need their own signed bridge connections. This is source
integration, not a verified runtime, deployment or release. The same database,
generation and complete state-enrollment payload compatibility remain mandatory;
this does not implement
arbitrary state migration or older-source replay.

## Separate evidence and effect authority

| Input or action | Authority |
| --- | --- |
| Original activation plan, caller, grant, reservation and acknowledgment | Exact independently archived activation scope and old root |
| New consume-input policy and planner/history originals | Current root; signed bridge binds both original contexts |
| Current state observations, current policy and consume writes | Current root and current configuration; genuine state/write replay |
| Planner endpoint, consume signer, grant/reserve/SQL/completion services | Independently configured current execution lanes |
| Token or browser-cookie release | Not authorized by consume; separate fresh release authority remains required |

The target and raw16 extractor retain the old activation originals and actual
old-token possession. `_ConsumeAttempt` separately seals the old planner bytes,
old activation execution configuration and old root, while its ordinary `_root`
continues to mean current authority. No old private key is delivered or used to
sign a new consume request.

The caller chooses ordinary acquisition only for the genuine current-mode target.
An archived target requires the separately configured v21
`historicalConsumeInputAcquisition`, with exact archive membership, old root,
configuration, interval and original execution/planning references. Missing,
mismatched or expired bridge configuration is a refusal, not fallback. The fresh
actor retains and rechecks the selected configuration and bridge lifetime.

## Real request and planner connection

Before historical target body one, the caller reserves both configured cold
candidate inventories within the existing planning allowance. Selection happens
only after genuine target admission. Full original issuer-policy verification
then precedes the unchanged durable consume claim and fixed issuer exchange.
Opaque raw2 output is retained before independent receiving admission.

The bridge-specific caller admission genuinely verifies the actual planner v3
and history v7 originals. It joins the retained issuer policy and old planner to
the selected archive, while current output configuration, runtime identities,
state enrollment and planner key/measurement must match the real current parent.
Ordinary admission remains strict and unchanged.

Protected planning obtains old provenance authority by re-admitting the private
custody owner's signed originals. It does not accept a previously successful
material object or caller-supplied old root as proof. Current state and write
replay stay current. The bridge uses a distinct private-input commitment domain
and commits the genuine old/current authority originals; ordinary input
commitments keep their original representation. Producer and receiver derive the
same choice from authenticated originals, never a posted profile selector.

The caller keeps fresh signing, authorization, reservation, the one-use SQL
exchange and completion directed at current `parent.consume_execution`. This
does not make those workers bridge-compatible: their v3/v4/v5/v6 custody profiles
still admit the old planner under the current root and lack a signed bridge.
They require separately versioned, purpose-bound producers and receivers, and
planner v3 needs an explicit historical-completion path. Planning-only v7 cannot
replace those roles. The public actor therefore retains its refusal of archived
effects. The new consume signing key must remain distinct from the HTTP signer
and both old and current activation caller keys. Original activation completion
is evidence, not permission to repeat activation or reset a consume attempt.

## Boundaries

The original work, clock floors, deadline and cumulative capacity remain in force
across cold intake, private planning and receiving. Added policy/planner/custody
captures are reserved before their bodies are decoded; valid individual originals
can still exceed the aggregate limit and be refused. These are source-defined
representation bounds, not measured process memory.

The separately authorized fresh `consume` caller is wired to this preparation,
but its historical execution gate remains closed pending those downstream joins.
Historical intent/proof and release purposes likewise retain their current-material
gate until their own original-authority joins exist. A completion result establishes
neither a released token nor a current browser session. Original delivery expiry,
durable attempt identity and uncertainty handling are unchanged; no automatic
retry, permission revival or source-label rewrite is authorized.

H05 remains partial. Purpose-specific consume grant/reserve/SQL/completion bridges,
later historical intent/proof/grant/release integration,
explicit older-source adapters, independent services and all production
acceptance gates remain open. Builds and execution follow the complete source
freeze; this document claims no passing tests or pilot readiness.
