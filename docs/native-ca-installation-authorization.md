# Native local CA installation authorization

`serverware/native_ca_installation_authorization.py` is the explicit Python producer and original verifier for the separate host-installation root grant. The paired native reader consumes the signed original again; a Python result is never its authority input. This is source-only, unbuilt and unexecuted. It does not attest installation or close a production gate.

The closed envelope is `{schema, payload, signature}`, with schema `serverware.signedNativeCaInstallationAuthorization/v1`. Its exact 16-field payload uses `serverware.nativeCaInstallationAuthorization/v1`, current shared `sourceRevision`, purpose `native-ca-installation`, and `trustMode: trusted-host-local`. The remaining fields bind the authorization ID, exact setup/delegation/target-request original digests, native runtime CA certificate DER/SPKI digests, full existing ten-field `caInstall`, five-field `networkOwner`, machine-ID digest, journal and original issue/expiry times. The [schema](../schemas/native-ca-installation-authorization.v1.schema.json) documents the closed shape; it is not signature or installer authority.

Encoding is sorted compact `ensure_ascii` JSON without a newline, at most 32 KiB. The Ed25519 signature is `ed25519:` plus canonical unpadded base64url for 64 signature bytes, over the payload-schema ASCII bytes, NUL and exact canonical payload. The public root is independently pinned canonical Ed25519 SPKI PEM, not a key claimed by the grant. Its exact PEM digest is separate from its public-key SPKI digest. The Python producer requires explicitly supplied protected canonical unencrypted Ed25519 PKCS8 bytes matching that root; it performs no key generation, file access, network request or secret publication.

## Original-only Python entrypoints

`_verify_on_work` takes `authorization_bytes`, `root_public_key_bytes`, `expected_root_pem_sha256` and the inherited `work`, `live_window`, `transport_deadline_ns`, optional ancestor `_current` and tightening-only `_additional_original_bytes`. `_produce_on_work` replaces `authorization_bytes` with canonical `payload_bytes` and `root_private_key_bytes`. The producer validates the payload before signing and round-trips the resulting exact original through genuine signature admission on the same work/clock.

The immutable verifier material contains the authorization/payload originals, their public commitments, original interval and live guard. It is diagnostic same-call material, not a completed install or externally accepted permission DTO. Both paths preserve the existing original work allowance and nonrenewing deadline. Keys are capped at 16 KiB. Preflight accounts originals and signing output within the existing 64 MiB ceiling; no fresh allowance or permissive fallback is created.

The positive nanosecond interval must be currently live, at most 300 seconds, and expire no later than `caInstall.expiresAtEpochMs * 1_000_000`. The worker additionally requires the whole grant interval to lie within genuine setup/native evidence/CA validity. Signature shape alone does not establish those joins.

## Scope and actual installer obligations

`caInstall` preserves the existing capability ID/token hash/expiry, destination path, UID/GID, mode `0644`, replacement choice and required old-certificate digest when replacing. `networkOwner.ownerUid` must be zero. Journal paths are absolute nonroot ASCII (codepoints 33–126), at most 4096 bytes and 64 components of at most 255 bytes; empty/dot/dot-dot components and backslashes refuse. Authorization IDs and journal namespaces are 1–128 characters, beginning alphanumeric and continuing with alphanumeric, dot, underscore, colon or hyphen. Journal device/inode are positive signed-64-bit integers.

The actual installer—not this shape/signature module—must join the protected token bytes, genuine same-connection native role-3/role-5 verification, exact setup/delegation/request originals, native runtime CA, independent live host/namespace ownership and destination state. It must enforce installation-root separation from the actual setup/delegation/native CA keys. The workload identity issuer CA is a different authority and must not be substituted for the native runtime interception CA.

The [local reservation journal](native-install-reservation.md) derives a stable slot from its independent namespace and signed capability ID, retains an irrevocable claim before effect and records exact completion after genuine destination readback. This grant neither reserves a legacy server token nor proves a previous server reservation. No token bytes enter the public grant or journal. Lost or partial outcomes do not authorize retry, and a matching completed slot never authorizes repeated installation. Hostile-host rollback resistance, full enrollment, firewall/canary authority and deployed evidence remain outside this grant.
