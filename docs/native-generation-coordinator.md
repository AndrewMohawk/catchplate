# Native generation coordinator

This is a source-only operational producer, not a verification verdict. It joins the explicitly selected custody runtime v5 to the five ordinary serving owners, the genuine native `CustodyResultEnvelope` key, immutable coordinator storage, and the existing generation-install consumer. The old runtime v4 and its wire responses remain distinct. No build, test, enclave, provider or deployment execution is claimed.

## Actual path

The bridge first obtains exact, independently signed local PREPARE effects from all five serving owners. It sends those original commands and responses to the native coordinator. The coordinator verifies each separate service history/root, current epoch, original grant, common Scope18 and unchanged deadline; it persists the original native history authority and exact proposal before returning its signed proposal.

The bridge returns that **actual endpoint request and signed reply** to all five owners. Each owner independently pins the coordinator key from its original grant, matches its own retained durable effect and unchanged business state, and durably records a second-round certificate using its existing service key. The coordinator consumes all five certificates, persists the complete conclusion, and only then returns the existing generation preparation result. It does not convert the first-round effect signature into a final certificate.

COMMIT requires that exact preparation and the same caller deadline. The five owners perform their real local commit first. The native coordinator durably records all five originals and the exact installation payload, then signs the existing installation envelope with the actually admitted result key. A second all-five certificate round binds that entire final artifact; its durable completion precedes the final response. The installation contains the original local commit receipt digests, while the enclosing result contains the later final certificates, avoiding a self-referential digest. Ordinary service operations stay fenced until their actual final certificate; the bridge stays poisoned/in-flight until the full result validates.

ABORT settles only the exact cold-generation admission and uses the same two rounds and original deadline. It is not a cleanup attestation, process-termination claim or permission to reuse the attempt.

The actual preparation timestamp is sampled after receiving real local effects. Its positive remaining interval must not exceed the unchanged configured maximum RPC duration. Neither that check nor a later certificate moves the original absolute deadline.

The separate supervisor signs `nativeGenerationCoordinatorAssignment/v1` for purpose `native-generation-installation`, using `serverware.nativeGenerationCoordinatorAssignment.signature/v1` and the existing signed-envelope preimage. Key admission alone is not this operational grant.

The final non-root owner retains exactly `shadow-generation-install-listener` and `generation-install-journal`; FD4 remains the actual privileged inspection channel. The fixed socket is `/run/serverware-shadow-generation-install/listener.sock`. `SelectedService::Generation` connects actual preparation, post-drop key admission, storage binding and the serving loop. In the existing parked proof cohort it is slot 3, and its independently assigned peer must be the observed slot-4 bridge. All children remain parked until the existing complete release checks succeed. The existing single-child supervisor also performs the real endpoint inspection.

The configuration supplies all five exact public grant and authority-history originals plus separately pinned history roots. The full canonical configuration must fit 65,536 bytes, including every member and complete historical material; no truncation is permitted. The native guest and all five ordinary service UIDs must be distinct, and neither can alias the independently assigned bridge peer. The ordinary five-service launcher/entry and grant memfds are the separate A producer; their software service signatures do not become Nitro attestations.

## History and durable state

The global custody epoch is explicitly independently assigned, not copied from an assignment revision or a software-service epoch. `keyHistory` retains at most 16 complete predecessor installation originals and every key in the actual 18-role custody set. Each original envelope, public material, purpose, current trust and revocation state is checked, with strict epoch/predecessor continuity. The complete 65,536-byte configuration bound remains tighter than individual field maxima. Expired, revoked, omitted or over-capacity history is refused, not renewed or silently shortened.

The first complete supervisor-signed authority original is itself durably retained. Later cold journal-head admission cannot replace the authority under which the installation was created. Current admission still independently revalidates the original scope, key authorization and trusted-time interval.

The journal directory is a supplied real ext4/XFS/Btrfs directory, owned by the final non-root UID/GID, mode 0700; tmpfs, overlay, network and read-only storage are refused. It initially contains the precreated mode-0600 `generation.lock` and immutable mode-0400 `genesis.json`, whose exact guest, assignment and services-original hash are independently pinned. The supervisor grant pins the exact admitted sequence and head. Each new `record-NN.json` is created once, file-fsynced, made immutable to the process's normal writer path, reread through retained descriptors and directory-fsynced. Full filename census, metadata identity, bytes and chain are retained. There are at most eight records, 512 KiB per complete record and 4 MiB total; the normal completed installation is exactly six records. File permissions alone are not anti-rollback authority; the independently signed head is mandatory. Partial, extra, missing or mismatching records are never repaired.

## Recovery is observation

Only the selected native profile emits `policyCustodyProductionGeneration/v5`, artifact `native-generation-recovery`. The independently signed `nativeGenerationRecovery/v1` contains the actual new Recover request, all five signed current observations, the admitted coordinator original hash and actual durable head, and either no installation or the exact retained PREPARE/COMMIT requests and completed results. The bridge independently verifies all originals and requires the observations to be exactly those it just obtained from its five authenticated sessions. The existing facade consumes this explicit variant.

Never-installed requires a genuine empty coordinator journal **and** all five service observations empty. Installed requires the actual completed six-record journal, all five exact committed effects, both original all-five certificate results and the original signed installation. Prepared-only, aborted, partial or unknown states refuse. The old `RecoveryNotReady` rejection is not used for native absence. A new replay label, timeout or fresh grant does not resume a phase, re-sign a final envelope, renew expiry or permit another contact. Recovery does not migrate a journal to a different guest/cohort or configuration.

## Remaining required owners

`RequestTermination` and `Settle` still require the separate real retained PIDFD/lifetime cleanup coordinator. This generation endpoint refuses those requests; neither an aborted generation nor a verified signature supplies their missing effects.

Independent signing/cold provisioning, durable initial journal inputs and actual process/peer observations remain deployment inputs. The existing successor binding is the real `ProductionCustodyConfiguration` semantic tuple, not a bridge/runtime-file hash. It includes the genuine kernel driver/retained descriptor identity. In this source, `from_verified_kernel_descriptors` has only its validation/rebuild caller; a source-owned privileged producer for new real driver/config material is still required. No predicted PID, caller-provided dictionary, grant/runtime digest fixed point or JSON input is claimed to fill that gap. This batch is not final Setup activation, full custody cleanup, or pilot acceptance.

The paired closed schema is `native-generation-coordinator.v1.schema.json`. Existing request, service epoch, effect and observation definitions remain referenced rather than widened. Whole service framing stays at its existing 4 MiB bound; the coordinator grant/journal limits are separately enforced.
