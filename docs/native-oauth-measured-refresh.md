# Measured due-refresh and captured-outcome recovery

This is a source-only, opt-in due-refresh path. It is not authorization-code issuance, deployment acceptance, provider testing, a confidentiality retrofit for material previously opened by a parent, or completion of every OAuth lifecycle. No runtime, NSM, KMS, provider or database action was performed while authoring this slice.

## Independent permission and confidential inputs

The actual signed `policyAuthorityServiceConfiguration/v6` must contain an explicit `oauthMeasuredRefreshPolicy` (`catchplate.oauthMeasuredRefreshAuthorityPolicy/v1`) and enable the fixed operations in the actual authority roles. The existing independently admitted configuration signer authorizes this purpose; there is no second self-selected issuance root or reused audit/currentness permission. Both verifier and planner independently validate the original enrollment, current purpose policy, exact original native role-4 signature and NSM COSE/chain/PCR evidence. The assignment names the actual boot/key/holder, release/policy/configuration/CA, binary, instance, provider, enrollment, encrypted client-material digest, KEK identity, provider TLS root digest and sorted exact credential IDs. An application enrollment alone grants no refresh.

The v7 native startup original pins the **independent authority root**, not a dynamic authority configuration containing its own native configuration hash. The genuine authority process retains its already-admitted original configuration and includes those exact bytes in its new signed measured-refresh response. The helper verifies the root signature, selected verifier key, purpose assignment and its actual retained native scope. Root certificates, configuration hashes and public evidence are not keys or permission by themselves.

`catchplate.oauthApplicationStartup/v2` retains the existing independently signed enrollment but supplies `catchplate.nativeOAuthApplicationMaterial/v1` ciphertext through the fixed private sealed descriptor. The descriptor path is `/run/secrets/catchplate-oauth-{google|x}-client-ciphertext`, maximum 64 KiB. The root descriptor is unchanged. The parent sees only the public client identity, redirect and purpose-bound AES-GCM envelope; token-form construction, parent refresh decryption and parent provider POST explicitly refuse this profile. Old startup/v1 bytes and development selection remain unchanged.

An **independent confidential provisioner** must supply the client material, broker KEK/KMS ciphertext and already-encrypted credential original. `native_oauth_refresh.seal_application` is the bounded offline envelope producer, not an HTTP endpoint or enrollment-signature verifier: its caller must admit the enrollment and keep plaintext/KEK outside the untrusted parent. The envelope binds the exact original signed enrollment hash and original client-material hash, has fixed 32-KiB padded plaintext, and uses a separate application-material AAD domain. This source does not generate a client secret, permit a host-readable KEK, or establish that an old input was never exposed previously.

## Actual connected flow

`--native-measured-refresh-startup` selects `catchplate.nativeStartupConfiguration/v7`. It requires the same actual encrypted service-token `Pending → Installed` owner, KMS recipient broker, serving-privilege owner, measured audit, native signer and credential-currentness profile as the v6 chain. All six plaintext bearer slots remain explicitly null. The added `measuredRefresh` configuration contains public root/scope pins, encrypted application originals, fixed provider TLS roots, exact credential IDs and an explicit `recoveryTargets` list. It is closed and cannot be selected by an HTTP response.

The real gate generation-metadata fetch calls `native_oauth_refresh::before_generation` for assigned credentials, under that original credential-operation deadline. It does not silently refresh a dispatch request already bound to version N. Existing strict lease responses and cached-send currentness remain authoritative. No CP SQL observation is claimed to undo an already dispatched effect.

The sequence is:

1. The private helper prepares `oauth.measured-refresh.inspect`; the genuine native custody owner signs a purpose-separated `catchplate.nativeOAuthRefreshStatement/v1` over those exact inputs, with a fresh NSM nonce bound to the statement and signature. The fixed HTTP route is `POST /api/data-plane/oauth-refresh`. Its transport token is admission to the endpoint, **not** issuance authority.
2. The actual cold custody client submits that original to the controlled writer. Only a genuine successful signed inspection may start the existing all-holder coordinator. It freezes complete local membership, drains actual native send owners, obtains every immutable acknowledgement and admits the barrier. An unavailable holder blocks. No timeout or lease TTL is an acknowledgement.
3. The helper independently verifies the exact signed request/response originals and root-signed configuration. If not due, it returns a current-version observation. If due, it opens the current credential and confidential application only inside the measured helper, commits the exact provider request, selects its original nonce/window and prepares the fixed claim. The writer atomically compares credential/generation originals, consumes the actual all-holder barrier, reserves complete retention capacity, creates the irreversible existing credential/version refresh slot and retains measured custody originals. A new operation name cannot evade an old consumed slot.
4. Only the definite claim receipt permits the helper's one provider POST. Google is fixed to `https://oauth2.googleapis.com/token`, X to `https://api.twitter.com/2/oauth2/token`; there is no caller URL, redirect, DNS, retry, reconnect, cookie or ambient proxy/root choice. Python/OpenSSL inside the helper owns TLS, hostname/root verification and token plaintext. The gate/parent relay carries bounded **TLS ciphertext**, selected by an admitted fixed literal endpoint. Neither a relay socket nor HTTPS alone is issuance permission.
5. Before replacement normalization, the helper encrypts the complete retained raw-response representation and issued-token material under deterministic artifact IDs and existing exact id/version envelope AAD. `oauth.measured-refresh.capture` atomically stores the encrypted originals, exact raw/issued hashes, received time and original native evidence in the protected store. Only its genuine definite signed receipt permits further processing; returning an encrypted candidate or an HTTP status is not durable storage evidence.
6. The helper applies the existing provider rules: Bearer, unchanged scope set/account/application association, omitted refresh token/expiry retaining the old original, explicit null refused, absolute expiry from the **original received time**, and X's actual changed-old-token subset. Google has no automatic old-family revocation. The replacement is encrypted for credential N+1, then `oauth.measured-refresh.commit` atomically updates the credential/head, creates the new strict currentness root, settles issued material and retains any X retired subset. Completion is reported only after the authenticated commit original returns to the same helper.

No broker or identity lock spans CP barrier waiting; the same gate's drain worker can progress. The actual helper remains retained by its live broker process and original native lifetime. Operation time is at most 30 seconds, shortened by admitted owners/enrollment/claim; no phase restarts the timer. Configured native bounds are due within 60 seconds, 30-second operation maximum, and 64 revocation rows. Authenticated complete populations retain the existing 64-row table ceilings and 32-row family-fence ceiling; these are explicit capacity limitations, not a global-population proof.

## Durable custody and fresh recovery-only processing

The protected `oauth_measured_refresh_custody` relation retains exact claim, capture, commit and optional recovery originals alongside the existing refresh reservation. It participates in actual primary/aggregate roots and the same atomic writer transaction, not an unrelated local success journal. The signed response family is `catchplate.policyAuthorityMeasuredRefreshRuntimeResponse/v1`; the narrow custody method returns only the exact request/response originals for these five purposes. It is not a generic signing or authority-configuration export.

An explicitly configured cold `recoveryTargets` entry chooses credential ID and the original N. A fresh independently admitted current measured assignment first inspects that stable slot, then `oauth.measured-refresh.recover` binds the exact durable custody row and captured input digest to a fresh one-use processing nonce/window. It authenticates the retained historical enrollment and original encrypted capture without requiring the old contact interval to become live again. The actual helper decrypts those retained originals, redoes deterministic provider normalization and may submit the fixed N+1 commit under that new recovery-only digest. This branch has **no claim or provider POST path**.

An already committed outcome is a read-and-audit observation of exact N+1 credential/head state; it does not repeat credential SQL. Missing raw capture, malformed/cross-associated records, absent independently admitted policy, changed incompatible source/configuration scope, or unknown outcome refuse. A consumed recovery processing claim cannot be reset or retried after interruption. The old contact lifetime and old signing authority are never renewed. Cross-source migration, arbitrary handover and recovery of a provider response that was never durably captured remain separate requirements.

## Bounds and explicit remaining work

The fixed URL-encoded POST body is at most 32 KiB, checked before the irreversible claim; this is an explicit narrower profile than the stored token field's bound. Provider response body maximum is 96 KiB, canonical raw headers 8 KiB, private originals 190 KiB, ciphertext envelope 256 KiB, helper channel 8 MiB, TLS wire aggregate 512 KiB and at most 512 relay exchanges. HTTP/1.1 accepts a complete bounded close-delimited, exact Content-Length or simple chunked response; compression, chunk extensions/trailers and conflicting framing refuse. Raw response storage is a canonical `{status, rawHeaders, bodyBase64url}` transport original, not a provider signature. Malformed or non-success replies can leave captured cleanup-only material but cannot produce a credential replacement. X retired and issued work use **new measured-refresh source purposes**; old exchange/refresh cleanup authority cannot consume them by alias.

Timeout, lost ACK, process death or missing reply after a claimed contact never proves noncontact. If raw bytes cannot reach a definite capture before the original lifetime closes, the slot remains consumed/uncertain; there is no claim that every possible provider effect became durable. The public route returns only encrypted/public originals and never token plaintext or a caller-selected success Boolean.
