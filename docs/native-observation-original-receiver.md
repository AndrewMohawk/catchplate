# Native observation preimage receiver

The actual delivery/v3 worker selects inner
`serverware.policyShadowRuntimeAccountingEvent/v2` only for
`candidate-evaluated` and `response-evaluated`. Its exact additional field is
the required, non-null `observationOriginal`. All other events and the old
delivery profiles retain the exact accounting/v1 fields. This is not a new
signing permission: the complete original remains inside the actual assigned
custody ledger append signature and existing durable canary delivery.

The closed request original preserves the actual active and candidate typed
plans, nullable compiled authority bindings, final active effect preimage and
ordered terminal evidence, actual capture/finalization times, and nullable
latency samples. The receiver recomputes the existing length-framed plan
commitments, typed terminal-effect commitments, final effect-result digest and
final active decision digest. Candidate plans must retain their actual
candidate-shadow purpose and both no-effect flags.

The closed response original preserves exact response facts, bound active
validation, the selected native released-response validation original and
candidate response-validation original. It rehashes all supplied preimages,
joins response commitments to the exact prior terminal and request originals,
and binds the response obligation root to the protected load receipt. No raw
response body, injected credential, fabricated Fleet envelope or replacement
transport proof is created. Inner transport/release commitments remain hashes
of their actual original owners, not decoded facts supplied by this receiver.

`authority_policy_canary_native_observation_originals.validate_protected_originals`
is invoked after the existing runtime or cumulative signature admission. The
individual route supplies its protected predecessors; cumulative routes supply
the complete signed prefix. Current protected generation publication fixes both
snapshots. Every non-null authority binding additionally invokes the exact A12
`retained_pair` and `require_binding` owners, rechecking the independently signed
compiler analysis against the installed signed policy/v2 maps. Null bindings
remain absent evidence. They are never inferred from an operation name, hash,
HTTP method or an expansion cell.

The helper returns partial original data keyed by actual ingress sequence:
`{request: (event, receipt), response: (event, receipt) | None}`. This is not a
verification capability. Any later readiness assembler must first use the
existing current-purpose, exact protected checkpoint and signature admission;
this helper cannot replace it. No `readiness_observations` implementation or
full `ObservationResult` is provided. Protected request facts, complete semantic
comparison, pilot membership and response-comparison derivation remain the
explicit next producer/consumer work; these partial documents alone are not
readiness, activation, client delivery or successful effect evidence.

Limits remain 8 KiB / 512 nodes / depth 32 per original, inside the existing
16 KiB event and 64 KiB runtime record. Cumulative limits remain 64 originals /
512 KiB, and all intake work uses the existing 8192-unit ceiling. Concrete
whole-batch work overflow refuses without a business mutation; no global bound
was raised. Larger production capacity remains follow-on work.

This source slice is based on exact .320, with immutable A12 classifier source
and the root worker event/v2 producer as separately composed prerequisites.
No build, test, parser, runtime or provider acceptance was performed.
