# Adopted operational cohort

This `.409` implementation joins the retained cold-core descriptor to an
explicit operational cohort. It is source integration, not a deployed pilot or
an independently approved production ceremony. The existing 36/46 source and
0/6 production checkpoints are unchanged.

## Actual ownership

`NativePilotLaunch.start_adopted` requires the genuine acknowledged
`ReceivedGenesisCore`, not its JSON observations. After the actual parked
cohort starts, the receiver is claimed before the ordinary-service watcher
thread starts. Its original monotonic/UNIX bounds remain in force.

`PilotEndpointInputs.prepare_adopted` owns Retrieval, Persistence, TrustedTime
and the new PublicationReconciliation listener. Retrieval retains a duplicate
of the actual received immutable core as its fifth descriptor; it never treats
the new hot ledger as the cold sequence-one store. Publication has a dedicated
retained owner and fixed listener path. C9 metadata alone is not an FD owner.

The receiver remains retained until real cohort closure and consuming parent
reap. Ordinary watcher shutdown precedes channel closure. Unknown release or
cleanup outcomes retain the owner graph; no retry or replacement window is
created. The native parent requires the exact adopted service selection,
closure/v5 and the actual readonly core descriptor before release.

## Independent authority

The [cold handoff](native-pilot-core-handoff.md) conveys custody only. Grant
issuance authenticates the independently signed adoption authorization and
literal validation input, current assignment/trust, target histories and C9.
Publication binds the actual Retrieval guest/key, not a future Retrieval grant;
Retrieval subsequently binds the already issued Publication grant.

Fixed packaged commands admit their complete exact input before reading a
private key. Legacy inputs cannot select the successor through a role name or
tag substitution. The adopted writer uses separate fixed destinations/caps and
exclusive publication with readback. It neither replaces prior files nor
provisions credentials. Signed payloads preserve the actual native signed-i64
canonical contract, even where source metadata readers permit full-u64 values.
