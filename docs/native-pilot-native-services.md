after the actual C9 and key/admission results. It does not launch these services

## Independently selected policy

Explicit `nativePilotSupervisorCommissioningPolicy/v9` adds only the literal
canonical `nativeServicesOriginal` to v8's sixteen fields. Its purpose is
`initial-driver-bootstrap-precreation-endpoints-generations-and-native-services`.
The outer 4 MiB limit and exact 77 capability selectors remain unchanged.
Earlier policy versions keep their original fields, purpose and authority.

The native-service fragment has eight fields:

- `apiVersion` identifies the closed native-service policy.
- `verifierSettings` selects ten endpoint verifier configurations: UID/GID,
  Nitro policy, collateral revocation, expected attestation and result age.
- `operationWindows` independently selects eleven original UNIX intervals.
- `spool` selects the generation identifier and independent origin verifier.
- `commitment` supplies the genuine existing startup-attestation receipt,
  independently pinned generation trust, issuer and selected fleet instance.
- `persistence` explicitly selects fresh initialization and permissions.
- `trustedTime` selects the parent port and approved clock-error bounds.
- `generationInstall` explicitly selects fresh initialization, epoch one,
  no predecessors and no historical records.

Static settings are not observations. The compositor derives verifier operation
identity and deadlines from the authenticated original Guest13, with no renewal
of its startup allowance. It retains independently selected Nitro expectations
alongside the real assignment/closure leaf and authenticated key/admission pair.
The actual verifier still checks the attestation document and complete measured
binding; a static PCR subset is not substituted for that result. Composition
does not create a Nitro verdict, credential seed, runtime receipt or process owner.
