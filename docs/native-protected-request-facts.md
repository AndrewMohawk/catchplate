# Native later protected-request commitment

This source batch connects the runtime v9 receiving factory to the ordinary
request's later facts commitment. It is not a pilot execution result.

The actual flow is immutable admitted request capture → installed candidate
classifier → worker-owned CommitRequest → native non-exporting HMAC owner →
the two actual durable/current-service transitions → settled RPC →
request-original/v3 → existing one-shot durable canary delivery → exact
protected opening/classifier/computation admission → full native detail.
Candidate evaluation itself stays pure and cannot dispatch candidate effects.

Runtime v9 alone selects the new native RPC result
`native-commit-request`, whose body is exactly `dispatch` and `computation`.
The former is the unchanged genuine completed dispatch; the latter is the
actual nativeShadowCommitRequestComputation/v1 signed original retained from
PREPARE through definite FINISH. The old Dispatch wire, both service
signatures, native computation domain and HMAC input algorithm are unchanged.
The bridge moves this original once into its real journalled RPC response.
No lookup can manufacture a missing completion or create a second attempt.
Legacy bridge runtimes retain their old reply and request-original profiles.

The receiving process checks the actual active RemoteNative owner, exact
request/result/binding, original BOOTTIME deadlines, current independently
assigned Ledger key/material and the distinct native computation signature.
Only this path attaches non-serialized provenance to RequestCommitment.
No raw key, software/Fleet alias, second HMAC owner or guessed signature exists.

The worker builds ProtectedRequestFacts from real pre-effect capture:
original method/scheme, SHA-256 of original canonical authority/path, nullable
original raw query, ordered canonical [header-name, header-value] hashes,
actual raw body hash, real classifier principal/route/profile/operation, and
the signed route's credential-slot identifier hash (never the credential).
The original captured timestamp is retained, not refreshed to the later
signing time. Its assignment window, current generation and original seal
deadline remain required, with installation guards held through completion.

The request original is an explicit v3: previous six fields plus exactly
`protectedRequest`. That record has four fields:
`apiVersion`, `openingReceiptSha256`, `samplingCommitmentSha256`,
`computationOriginal`. Facts, context and HMAC result are the actual canonical
artifacts in that signed computation, not duplicate re-created statements.
The actual installed runtime v9 selection is read from the retained receiving
closure; neither a request flag nor an environment variable selects it.

Native early BeginIngress sampling remains a different commitment with its
unchanged domain and reduction. All opening/event/lifecycle receipt fields
retain that sampling digest. Final detail uses the later full RequestCommitment
SHA for captured facts, while its actual opening reference preserves the early
sampling association. Final drain and detail decode the explicit early shape;
missing later facts cannot turn into evaluation/readiness credit.

Limits remain 8 KiB / 512 nodes / depth 32 for the full observation original,
16 KiB for its signed event, 64 KiB for the record, and existing whole-batch
work/response ceilings. Decoded artifact work is charged separately. Large
header sets, plans or signed-computation originals may exceed these temporary
pilot capacities; that is an explicit unready result, not omission, splitting,
deadline renewal or retry authority. The initial request original is bounded
before HMAC contact; complete signed output is bounded again before append
and delivery. A post-computation overflow does not erase that real completed
computation or authorize repeating it.

No build, test, parser, signing, launch, provider call or runtime acceptance
was performed. Actual independently provisioned authorities, complete runtime
v9 endpoint cohort and ordinary effects remain deployment prerequisites.
Full pilot acceptance and production-scale capacity work remain open.
