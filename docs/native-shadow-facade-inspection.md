# Native bridge to gate peer inspection

This source connects the full-admission native bridge's four incoming facade
sessions and outgoing ordinary service/authority connections to its actual
retained root parent. It does not create a gate-side native configuration,
install a generation or provide signed lifecycle/settlement evidence.

## Connected owner

The explicitly selected full-admission bootstrap prepares the inspector through
the same genuine `ParentInputs` that already owns proof-client inspection.
The parent retains the real production listener and its path identities, exact
signed runtime configuration and configured gate identity. Older bootstrap and
host service paths remain unchanged.

After drop and full configuration activation, the bridge retains an acceptor
from that same private channel. Each actual accepted socket is registered once,
in four fixed ordinal slots, under the original startup deadline. The parent
checks the real kernel peer PIDFD, PID/start, executable, cgroup, security label
and configuration-generation identity using the existing direct measurement
implementation. It retains that exact connected socket, not a supplied verdict.

The source-owned common session has a distinct native-facade inspection branch.
Normal RPC queueing and request/response transport remain unchanged. Every peer
revalidation returns to the same retained parent, checks the same socket
device/inode and fixed peer, and authenticates the reply through the parent's
kernel credentials/PIDFD and exact request digest. A separate closed inspection
API shares the serialized proof channel but never adds a facade alias to the
proof endpoint enum. No arbitrary target PID, path, executable or expected-peer
object is accepted over this channel.

Pending parent replies remain owned under the original lifetime; another
request cannot replace them. Neither admission nor revalidation resets startup,
grants, the process lifetime or an uncertain session ordinal. There is no host
inspection fallback if the native owner fails. This parent remains privileged
trusted code, not measured remote evidence or a read-only security sandbox.

## Outgoing services and final-role listener

The same signed runtime selects five ordinary services and ten signer roles.
Actual native proof/signer owners are excluded by the source-owned selection,
never by a caller list. Each remaining endpoint owns a fresh unconnected
nonblocking seqpacket socket and an exact root-owned read-only directory FD.
The independent C9 delivery pins their real identities. The bridge connects
through that directory only after final privilege drop, before its handshake.
Ordinary framing enables SCM credentials but not automatic SCM PIDFD delivery.

The parent retains exact duplicate socket/directory owners and the original
protected path identities. Its separate closed outgoing API admits only the
source-selected ordinal, exact socket identity and configured peer. Handshakes
and later traffic reuse the same opaque inspected session; they do not recreate
a direct-proc owner after drop. An uncertain connection consumes its slot.

Before gate connection, the actual bridge re-listens under its final identity.
Linux's [Unix listener implementation](https://github.com/torvalds/linux/blob/master/net/unix/af_unix.c)
updates the credentials copied by later connections. This source dependency is
not runtime proof for a deployment kernel. Only explicit bootstrap v4 sends
the fixed listening notice over the original authenticated channel; its actual
listener identity, observation and signed scope are checked by the retained
[lifecycle owner](native-shadow-driver-lifecycle.md). Earlier scopes receive no
new notice. Listening does not disarm startup or claim construction/readiness.

## Remaining connections

The gate still needs its genuine native configuration factory and actual
four-session connection to the bridge. The newly connected lifecycle receiving
owner observes the real parent and subtree; it does not confer that authority.

Operational descriptor/reaper observation and its signed association remain
distinct from bootstrap measurement and socket authentication. Remaining
ledger/Setup effects, independent provisioning and connected acceptance are
still required. Source was not built or executed; broad testing remains deferred.
