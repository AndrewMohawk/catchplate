# Native shadow guest key admission

This source adds a distinct no-arguments, empty-environment entrypoint,
`serverware-policy-shadow-custody-guest`. It does not run, rename, or upgrade
the six `TrustedHostNoTee` service constructors. It acquires assigned encrypted
local keys, produces actual Nitro evidence, admits the independent verifier's
result, and retains those owners until their original authority expires. It
does not publish readiness, expose signing/key RPC, or produce receipt/proof
service success. Build, deployment and runtime acceptance are unperformed.

## Actual entry and provisioning contract

The fixed root:root0400, single-link cold original is
`/etc/serverware/native-shadow-guest-launch.json`. Its closed v1 launch has
`deliveryConfiguration`, `delivery`, `trust`, `timeBootstrap`, `assignment`,
`closure`, `keys`, `encryptedKeys`, `admission`, and `verifierTransport` pins.
All point to independently protected, already provisioned originals; the last
has the existing fixed `/etc/serverware/native-shadow-public-exchange.json`
path. Pins select and retain bytes; signatures and actual owners confer their
specific authority. No policy, external verifier key, time key, supervisor key,
trusted epoch or independently assigned challenge is generated by the guest.

The actual parent must execute the source-fixed static AMD64 binary from the
sealed zero-link root:root0500 executable admitted by the native closure. The
fixed immutable claimant runtime remains
`/opt/serverware/native-shadow-custody-runtime.squashfs`; it must contain the
same `/usr/local/bin/serverware-policy-shadow-custody-guest` and the complete
independently assigned closure inputs, plus a root:root0555 `proc` mount target.
This image is distinct from both the shadow-key Python helper image and the
independent external verifier image. This batch does not supply the parent
sealed-exec launcher or this static custody image's packaging producer.

FD3 must be the genuine private AF_UNIX SEQPACKET parent channel. C9 verifies
its actual parent PIDFD/start/credentials against `getppid`, signed boot/time
namespace, role UID/GID, original startup/lifetime and exact activation slots
6 through 69. The entry refuses extra inherited descriptors or unsigned
activation slots; it never detects a profile from an optional FD. Signed C9
role slots are not response-v2 role assignments. C9 retains the encrypted
inventory only: no legacy plaintext local-key slots are accepted by keys v2.

Post-C9 assignment, closure/key/admission authorization, time bootstrap and
verifier transport originals are independently pinned by the launch after C9
exists. They must stay outside C9/runtime/closure transitive hashes. This avoids
predicting PID/start/cgroup values and avoids a self-pin digest cycle.

## Genuine time acquisition before key contact

The source arms kernel CLOCK_BOOTTIME SIGKILL timers for the already-signed
C9 startup and lifetime before NSM, image or helper preparation. It retains
actual parent/process/boot originals across the permanent role drop. The
startup timer is disarmed only after genuine external key admission; the
lifetime timer is never reset. Parent death remains fatal before and after
the drop. Core dumps are disabled and the process is nondumpable before even
the ephemeral time key exists.

The separately protected time bootstrap is exact seven fields: apiVersion
`serverware.nativeShadowGuestTimeBootstrap/v1`, the actual C9 `guest`,
`signingKeyId`, fixed `parentPort`, `maximumBracketNanos`,
`timestampErrorNanos`, and `maximumClockRateErrorPpm`. The public time key is
independently pinned by the held trust original, distinct from assignment and
every authority-role key. This bootstrap admission uses no epoch-dependent
grant, avoiding a trusted-time/closure circular dependency.

Before the time quote, a separate preparation retains and checks the real
sealed static executable against the protected closure pin and the same C9
runtime binding, including actual executable mappings and single-thread
identity. This consistency owner grants no time-dependent closure authority;
the later full signed closure/image admission must consume the same origin
and executable identity after genuine time acquisition.

The actual guest opens the genuine retained NSM device, receives the issuer's
signed fresh challenge, generates one ephemeral Ed25519 key, samples BOOTTIME
before the fixed-purpose quote and after it, and signs only that exact bracket
and quote hash. The NSM public key is that actual ephemeral public key, not a
local-role root or a KMS recipient. The independent issuer verifies original
COSE/PKI/PCR/module, the independently pinned C9 delivery/config originals,
challenge, possession and bracket; see `native-shadow-guest-time-issuer.md`.

Wire tags are `SWNGTC1\0`, `SWNGTE1\0`, `SWNGTA2\0`, each followed by a four-byte
big-endian length and at most 64 KiB canonical ASCII JSON, without a newline.
There is no request half-close: the existing raw parent relay tears down both
directions on first EOF. The guest requires EOF only after the complete signed
anchor. Transport carries public signed bytes and claims no confidentiality.
It supplies neither issuer identity nor a trusted epoch by itself.

The v2 anchor binds the exact challenge/evidence/quote originals and actual
before-sample BOOTTIME. Its earliest/latest epoch interval includes at least
the issuer's conservative millisecond quantization, admitted timestamp error
and bracket drift. The guest widens it with elapsed BOOTTIME and the signed
rate-error bound; no midpoint or arrival clock is substituted. These error
bounds are explicit independent deployment assumptions, not a hardware SLA
proved by the signature. Bracket is at most one second, error at most one
second, rate at most 10000 ppm, challenge at most 30 seconds, anchor at most
300 seconds. Ambiguous validity refuses rather than waiting or renewing.

Every actual native admission freshness path checks not-before against the
earliest and expiry/age against the latest: trust/key/checkpoint, policy
assignment, closure, encrypted delivery, external transport, admission and
result. Existing exact `TrustedTime` implementations keep their old exact
pair. The old point-anchor v1 is not accepted here.

## Root installation, key and evidence owners

After time and assignment admission, the guest prepares the actual closure,
NSM and pinned KMS helper while still root. It creates a private mount
namespace, installs a read-only clone of genuine local procfs into the held
immutable root, chroots, drops groups, real/effective/saved UID/GID and all
effective/permitted/inheritable/bounding/ambient capabilities, sets NNP and
nondumpability, and consumes the same originals under the signed final role.
It does not substitute the new image's `/dev` for the held original NSM device.

The encrypted-key helper's separate genuine RSA Recipient evidence precedes
local-role key acquisition. The unchanged fixed KMS key/context/TLS/blob
selection and original deadline apply. Plaintext exists only in the pinned
helper and final-role owner, never a parent RPC or newly written seed file.
The independently assigned full18 inventory remains separate from the actual
local subset (at most16, excluding external verifier and supervisor).

Key admission uses its own supervisor-purpose assignment/domain and separate
possession and result domains. The actual post-create context binds retained
self/parent PIDFD/start, raw cgroup bytes, installed root and closure, C9 and
original observed BOOTTIME. These observations are not a dispatch driver,
reaper, cgroup-kill proof or settlement capability. The independent verifier's
explicit protected configuration v2 authorizes static scope but derives the
dynamic context from genuine quoted bytes and local key possession. Legacy
verifier v1 and legacy closure/production constructors are unchanged.

Only the guest's current separately assigned `CustodyAttestationVerifier`
public key verifies the new exact result purpose. The external supervisor's
shape check merely bounds output; real signature/nonce/quote/full-root/current
checkpoint admission still happens here. The guest retains all live owners
and originals, publishes no ready notice, and has no retry/reset path.

## Remaining actual integrations

The root-owned fixed parent launch/image producer, dedicated fixed-peer
inspection, actual dispatch/reaper/settlement producer, ten receipt and four
proof endpoint servers and their same-origin serving lifetime joins remain
required. Independently provisioned signed launch/C9/trust/KMS/verifier/time
configuration and secrets are not created by this code. The independent time
issuer's installed runtime/transport must be deployed separately. Private
namespace/process exit is not reported as successful mount/loop retirement;
the parent must observe and reap the actual child. No full native custody,
pilot readiness or production acceptance claim follows from this source.
