# Native retrieval pair: precreation before independent assignment

The explicit fixed serverware-native-shadow-retrieval-pair parent creates the real server and bridge children before their dynamic cross-peer assignments are authored, then admits the exact post-create originals before releasing either child. It does not complete the full custody bridge, issue a driver capability, or publish readiness. No build, process, mount, signer, provider or kernel acceptance was executed for this source slice.

## The actual dependency

The old parent admits C9 before clone. Bridge C9 runtime contains the server's expected peer identity; the server operational grant contains the bridge identity. The immutable image also contains that runtime original. A process cannot be substituted after authoring PID/start/executable-inode fields. Two ordinary parents additionally open the same fixed launch/image names. Predicting IDs or calling the root trampoline a final-role measurement would not solve this.

## Fixed two-phase flow

1. Protect the closed pair configuration at /etc/serverware/native-shadow-retrieval-pair.json and separate purpose-signed precreation envelope at /etc/serverware/native-shadow-retrieval-pair-precreation.json (root:root0400, one link, <=32KiB, protected ancestors). Configuration pins both existing cold C9 configurations, their common independent delivery public key, and the static executable SHA. Distinct nonroot UIDs and existing reserved-ID guards are mandatory.
2. The parent takes only a connected private root AF_UNIX SEQPACKET at FD3 plus stdio; no arguments/environment or guessed mode. Kernel original peer credentials/PIDFD are retained. Transport is not signing authority. Precreation independently authenticates actual boot/time namespace, invocation and original issued/startup/lifetime.
3. Before executable, namespace or clone effects, the original absolute CLOCK_BOOTTIME lifetime SIGKILL watchdog is armed. The parent reads the pinned static guest from fixed root0400 /opt/serverware/native-shadow-custody-guest.elf (<=64MiB), validates actual static ELF and creates two root0500 fully sealed zero-link memfds. It clones two actual PIDFD-owned children. Each syscall-only trampoline installs parent-death SIGKILL, creates its private mount namespace and parks before exec. Before changing its own image view, the parent requires the actual child kernel credentials/PIDFD on the fixed park acknowledgment and observes a genuinely distinct mount namespace; that ordering notice grants no authority.
4. The parent emits one canonical nativeShadowRetrievalPairOriginals/v1 frame. Each observation contains only actual clone PID/start and actual retained executable device/inode/length/SHA. These are assignment inputs, not final credentials, cgroup/SO_PEERSEC measurements, native quotes, ready flags or deserializable process owners.
5. Independent authorities supply complete C9/runtime/launch/closure/key/time/verifier and server operational-grant originals bound to these inputs. A separate purpose-signed pair release commits the exact observation. Both C9s preserve the original boot/time namespace, issued/startup/lifetime and invocation. Final UID/GID and remaining peer14 fields remain independently assigned expectations, enforced by unchanged real serving inspectors, not measurements projected from the trampoline.
6. The release transfers actual signed activation descriptors, server then bridge in each exact6..69 order. Parent checks device/inode/mode/UID/GID, role, socket and unique descriptor identities. Both cross-peer PID/start/executable tuples must match the same live parked owners. Server selects nativeShadowRetrievalGuestLaunch/v1; bridge selects nativeShadowRetrievalBridgeLaunch/v1. Full existing bridge prerequisites remain mandatory.
7. Each pinned full image is admitted through the existing sealed-copy/readonly-loop/SquashFS owner. Its actual executable must be byte-identical to that child's already allocated memfd. Closure/runtime/BPF/build checks remain unchanged. The private temporary parent image-path view is detached after admission while its actual source FD/mount reference remains retained through reap; no mount-destruction claim follows. Each child receives its held launch/image originals and binds them readonly at the unchanged fixed names in its private namespace.
8. Only after both sets are admitted does the parent send each one-shot internal gate and genuine inspection/activation FDs. The unchanged fixed guest executes from the same memfd, repeats native C9/closure/time/encrypted-key/quote/external-result admission, permanently drops privilege and enters the selected service. There is no atomic two-process ready claim: a failure after the first gate stops both.

## Retained ownership and cleanup

The same root pair parent runs both purpose-fixed peer inspectors. Actual child/process/socket/PIDFD ownership and strict final-role/exec/cgroup/label checks remain mandatory. No role receives DAC or ptrace capabilities; no arbitrary PID/path/read API is added. The trampoline interprets no caller command/argv and performs no heap or lock work after clone. Root mount/admission is explicitly authorized preparation, not a new sandbox-confinement claim.

The original parent remains the actual FD3 lifetime peer through exec. The fixed250ms shutdown reserve only narrows original lifetime. Failure/exit stops BOTH children before either reap wait. Matching waitid(P_PIDFD) terminal evidence and same-PIDFD reaps precede releasing image/executable/original owners. Timeout is not death; unproved cleanup exits fail-closed with watchdog/PDEATHSIG intact. No unmount/loop or descendant-settlement success is claimed.

The child targets must already be protected root0400 regular files at /etc/serverware/native-shadow-guest-launch.json and /opt/serverware/native-shadow-custody-runtime.squashfs. Empty placeholders are mount targets, never admitted originals. Host files are not rewritten or wildcard-cleaned; bindings are mount-private. The separate static executable deployment input is not assumed installed by adding the new binary.

The [closed schema](../schemas/native-shadow-retrieval-pair.v1.schema.json) defines canonical ASCII/integer noLF frames <=32KiB: observation6, precreation envelope3/payload9, release envelope2/payload8. Distinct explicit Ed25519 domains followed by NUL and the full canonical payload use the independently pinned existing C9 delivery key. No supervisor, verifier, local-role or authority key is generated or reassigned.

The closed sign_precreation/sign_release functions in serverware/native_shadow_retrieval_pair_assignment.py author explicitly approved input artifacts using an already held independent key. They do not authenticate caller observation provenance or construct retained owners. The operator must retain the genuine private parent channel and compare its observation before approval. Existing RetrievalActivation, sign_retrieval_delivery and one-use take_for_launch supply the actual server bound-not-listening socket/object directory; bridge activation and other endpoint originals must also genuinely exist. Integer lists are not FD custody.

## Remaining producer and acceptance boundary

The original <=30s startup includes independent post-create approval, dynamic runtime/image materialization and both guests' time/KMS/verifier startup. Those real issuance/build/deployment arrangements are not fabricated here and may fail the bound. Failure requires an explicitly new approved invocation, never internal retry/renewal. An operator integration must still perform the bounded private-channel authoring exchange and source-owned descriptor transfer; the data-signing helper is not that launch/transport owner.

The bridge still requires actual five service sessions, ten receipt signer endpoints, the other three proof endpoints, histories, recovery/journal, facade sessions and genuine dispatch/reaper/settlement ownership. Only the retrieval pair is orchestrated here. This is not whole native custody, proxy readiness or credentialed-pilot permission. First builds and kernel/mount/PIDFD/NSM/KMS/time/verifier/fs-verity deployment plus the full authenticated credential flow remain unverified.
