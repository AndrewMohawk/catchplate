# First native shadow retrieval proof service

Source-only implementation; no build, fs-verity, socket, Nitro, KMS, issuer, verifier, or runtime acceptance has been performed. This is one actual read-only proof producer, not complete native custody or a production-ready bridge.

## Selection and real owners

The fixed guest supervisor and guest accept an additive closed launch:
`{apiVersion:"catchplate.nativeShadowRetrievalGuestLaunch/v1",keyAdmission:<unchanged launch11>,retrieval:<protected path/SHA pin>}`.
The original key-admission launch11 remains valid and retains its no-service hold behavior. Old TrustedHostNoTee constructors/labels and their peer checks are unchanged.

The separate retrieval original is root:root0400, canonical ASCII/integer JSON with no LF, <=64KiB, outside the transitive C9/runtime/closure digests. Its supervisor-signed assignment binds the actual post-create C9 guest13, full assignment and key-authorization digests, exact original production proof scope, actual peer14 and checkpoint/revocation/window. The operational purpose/domain is `catchplate.nativeShadowRetrievalServiceAssignment.signature/v1`, using the existing signedEnvelope/canonical-profile framing. Only the independently assigned current CustodySupervisorCapability key can authorize it. Delivery, key possession, an external admission result, or a protected file alone is NOT that operational grant.

The guest still performs the genuine root C9 admission, original BOOTTIME timers, independently issued trusted-time interval, immutable execution closure, permanent role drop/capability clearing, encrypted local-role acquisition, actual NSM possession quote, and independent external result admission. Retrieval additionally requires possession of the actual independently assigned CustodyRetrievalResponse key. No public sign(bytes), key return, dispatch capability, synthesized ProductionCustodyDriver, or ProductionCustodyProofScope constructor is added.

The scope remains an exact data-only original from the genuine production configuration. The service verifies its assignment/revision/realm/namespace, full key root, closure/seccomp, store/retrieval authority keys and scope-binding recipe. Its production-configuration digest is an independently signed original pin, NOT a reconstructed driver. The genuine driver/configuration producer and all operation authority remain separate.

## Final-role listener and fixed inspection

C9 retains exactly two signed activation originals in its unchanged contiguous6..69 slots: `retrieval-listener` and `retrieval-objects`. This profile uses the signed production-bridge role UID/GID; no five-service key or response-v2 assignment is reused.

The listener must be freshly source-prepared AF_UNIX SOCK_SEQPACKET, bound but NOT listening, at `/run/catchplate-shadow-retrieval/listener.sock`. No replacing an existing path is authorized. Its directory is root:root0711 with no writable ancestor; world execute permits traversal only, not listing/write, and this is not a secret directory. Socket pathname ownership is the signed guest UID and actual pinned peer primary GID, mode0660. C9 separately pins the actual socket descriptor stat original. The source parent retains directory/path identities and the actual bound socket; the guest calls listen and accepts exactly one connection only AFTER permanent final-role drop and genuine key/operational-grant admission. A root-created connected socket cannot substitute for that final-role listener identity.

The parent creates the extra private FD4 inspection pair and supplies it only in the explicit retrieval profile; FD4 is absent/rejected for old launch1. It is source-owned consistency/liveness, not unsigned authority. FD3 stays the exact original parent lifetime channel with no readiness messages. The fixed clone child receives FD4 from retained descriptors, never an ambient caller slot.

The root parent is also the finite fixed-peer inspection TCB. On the one connection admission, the actual accepted socket plus its actual connection PIDFD pass over FD4. The parent checks its fixed local address against the retained signed listener, then constructs the existing AuthenticatedInheritedSeqpacket owner over that real connection with independently assigned peer pins. It retains that socket/PIDFD/executable owner. Subsequent inspection requests contain only phase, strict sequence, exact frame digest and narrowing original deadline plus the actual packet PIDFD; there is no PID/path/hash-as-measurement RPC or second target.

Before dispatch and before each response attempt, the root repeats the actual existing PIDFD/start/current executable/cgroup/SO_PEERSEC checks before and after joining the packet PIDFD. Child requests carry actual kernel SCM_CREDENTIALS and SCM_PIDFD and are compared with the parent's actual clone PIDFD/start/parent ownership. Replies similarly identify the child's actual root parent, carry exact request echo and expected measured process binding, and contain no descriptors. A reply waiting for channel capacity retains both the original child packet and target PIDFD and repeats those actual checks before emission. The guest retains its actual connection and packet PIDFD/credentials; no wire object becomes the opaque host measurement owner. Both Linux SO_PEERPIDFD and per-packet SCM_PIDFD are mandatory, without a compatibility fallback.

No inspection capability, supplementary group, or dumpability change is granted to the serving guest. The existing privileged launch/lifetime parent is now an explicitly documented inspection TCB; this slice does not claim it is a separately seccomp-confined minimal inspector. No ptrace/memory/exec/network operation is exposed through its fixed channel. The same original startup and lifetime bounds remain in force, including the parent's existing narrowing cleanup reserve and actual same-PIDFD kill/reap ownership.

## Real exact retrieval and unchanged client wire

The guest serves the existing `ProductionAuthorityEndpoint/v4` Retrieval endpoint, and ONLY the actual `VerifyProof -> VerifyAssignmentBoundRetrieval` request. The real caller is `RpcPersistenceVerifier::verify_assignment_bound_immutable_retrieval` through `ConcreteFiveV3ProductionAuthoritiesV4::verify_retrieval`. Endpoint/request/replay/full-request hashes, original deadline and exact original scope must agree. Legacy unscoped retrieval, persistence, generation, dispatch and arbitrary read/sign operations refuse.

The retained object directory is root:root0555, opened O_RDONLY, with original complete stat identity preserved for the service lifetime. Each object is root:root0444, one-link regular, O_NOFOLLOW/O_RDONLY, 1..1MiB. The service requires ACTUAL `FS_IOC_MEASURE_VERITY` (0xc0046686), SHA256 algorithm1, size32, nonzero measured digest, before/after the read and through response signing/emission. A read-only mount, SquashFS, ordinary content SHA, or caller-provided verity string is not fs-verity. The guest enables no verity and performs no write/repair/install operation.

Object exact5 and grant/launch/IPC declarations are in [the schema](../schemas/native-shadow-retrieval-service.v1.schema.json). The object contains the exact scope SHA, signer role, canonical receipt original and exact signed-authority payload. The authority payload must equal the existing assignment-bound canonical tuple. Define H(domain,parts) as SHA256(domain ASCII + NUL + each u64BE byte length + bytes). Then:

- retrieval ID = H(nativeShadowImmutableRetrievalId/v1 with full catchplate. prefix, [prefixed namespace ASCII, exact object original]).
- filename = raw64hex(retrieval ID) + .json; no caller path.
- retrieval proof = H(nativeShadowImmutableRetrievalProof/v1 with full catchplate. prefix, [scope original, canonical role JSON, prefixed retrieval ID ASCII, receipt original, authority original]).

The bounded object is actually read, decoded exactly and compared with every requested byte. Its held immutable descriptor remains live and is rechecked until response emission. Only then does the genuine retrieval-role key sign the unchanged exact v4 endpoint reply/preimage. File absence, mismatch, expired/drifting authority, wrong peer or unknown operation produces no signed success. At most256 distinct replay IDs are accepted in one original lifetime; conflicting reuse refuses, and all identical requests still repeat the actual read. There is no persistence/durability assertion in this read proof.

## Provisioning and remaining path

The [operator producer/installer](native-shadow-retrieval-provisioning.md) derives objects and grants from supplied originals and the independently provisioned supervisor signer, and enables/measures actual fs-verity on a bounded new store. This source tool has not been run. A real outer launcher must still install the fixed fresh listener/directory and signed C9 activation originals. Those inputs are not synthesized here, and native kernel/filesystem support remains unverified. Scope and dynamic peer assignment require real already-created original owners; predicted PID/inode values are not acceptable.

The existing full production bridge still requires all five legacy authority services, all ten receipt endpoints and all four proof slots. This implements the native retrieval server path only: ten receipt services and the other three proof producers, actual persistence/writer, full production driver/reaper/settlement and outer coherent launcher remain open. In particular the existing client-side AuthenticatedInheritedSeqpacket cannot inspect a distinct nondumpable native server from an unprivileged bridge; its genuine dedicated client inspection-owner/factory join is still required. No dumpable/same-UID/root-serving fallback is added. There is no whole-bridge readiness or successful parent exit claim. Independent first build/deployment and full end-to-end credential/runtime acceptance remain outstanding.
