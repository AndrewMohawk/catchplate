# Native shadow verifier public exchange

This is a purpose-fixed transport for public possession evidence and an independently signed verifier result. It provides no confidentiality, TLS identity, claimant key custody, or readiness authority. A parent/network adversary may observe, delay, truncate, substitute or deny these public bytes; only the guest's existing independent signature/quote/current-trust verifier can admit a result. No existing TLS or mTLS path is changed.

The paired contract is [native-shadow-verifier-transport.v1.schema.json](../schemas/native-shadow-verifier-transport.v1.schema.json). The existing [Nitro verifier](native-shadow-nitro-verifier.md), [immutable runtime](native-shadow-verifier-runtime.md), and [child confinement](native-shadow-verifier-child.md) retain their distinct ownership and authority boundaries.

## Guest authority and one-shot caller

The explicit native launcher first calls `PreparedNativeCustodyKeys::prepare_external_verifier(pin, trust, time)` during the same genuine C9 root-preparation window. The exact2 `NativeVerifierTransportPin` selects only `/etc/catchplate/native-shadow-public-exchange.json` and its independently provisioned SHA. The retained actual file transfers through the genuine key-owner `bind` and final-role drop. Then `NativeCustodyKeys::verify_external(trust, time)` operates on that owner, its original C9 delivery/closure/process and startup deadline. Old host profiles and direct inherited-file verifier execution do not select it automatically.

The public configuration is a separately protected root:root 0400, singly linked, at-most-32-KiB canonical ASCII original with protected ancestors. It contains closed `catchplate.nativeShadowVerifierTransport/v1` configuration2 and authorization2 with payload20. The independent launch selector is provisioned **after** the C9 original exists, outside C9/runtime/closure transitive digests. Storing the authorization or its pin inside the delivery it signs would create a digest cycle: the full authorization binds that delivery's digest and key authorization. The pin is consistency/selection, not authority; the full signature remains mandatory. Final-role checks read the retained actual descriptor/stat/bytes, never reopen a chroot-hidden path or demand the old root UID. No caller supplies a URL, PID, public key, evidence, success DTO or replacement deadline.

The independently assigned supervisor-capability authority signs the full canonical payload under `catchplate.nativeShadowVerifierTransport.signature/v1`, using the existing signed-envelope/ascii-integer signature framing. The payload binds the actual assignment/revision/full18 root, key-authorization original, exact guest binding (configuration/delivery/runtime pins, final role, UID/GID, boot/time namespace, invocation and original windows), original challenge, fixed parent VSOCK port, original checkpoint/revocation and wall-clock validity. It separately pins the actual `CustodyAttestationVerifier` key ID, SPKI and public-material digest from the independent full inventory. Both roles are resolved at the genuine current trust checkpoint; no local claimant role becomes the verifier.

Only after those checks does the owner generate its own once-only NSM possession evidence. The request is the exact canonical evidence retained by that owner. The response is delivered unchanged to `accept_verifier_original`, which requires the actual quote digest/full root and the existing independently signed TEE-result admission. Shape, a relay address or successful socket I/O cannot activate custody. Any failure poisons that native owner; there is no quote/reset, network retry, fallback or new allowance.

## Exact framing and relay behavior

| Direction | Fixed 8-byte prefix | Length | Original |
| --- | --- | --- | --- |
| Guest to external verifier | ASCII `SWNSVQ1` followed by NUL | unsigned 32-bit big-endian, 1–131072 | canonical Evidence7, no LF |
| External verifier to guest | ASCII `SWNSVR1` followed by NUL | unsigned 32-bit big-endian, 1–32768 | canonical Result2 with existing ResultFields22, no LF |

The guest keeps its write direction open after the request. The actual existing `enclave_tls_relay_io_v1` relay stops **both** read directions on the first EOF and drains only its already pending buffers; it does not preserve request half-close. Waiting for request EOF would therefore break a real reply. The external receiver consumes exactly the length-framed request and checks for queued extra bytes or premature closure before/through publication. This is only a bounded queued-data check, not proof that future trailing bytes cannot arrive.

There is exactly one exchange per connection. After the whole successful result is sent, the external side closes; the guest requires EOF immediately after the exact result original. A failure closes without a success frame. There is no HTTP, DNS, redirect, caller-selected operation, multiplexing, request-side half-close or reconnection. The existing fixed parent relay independently retains its own literal TCP target, enclave CID and parent-local original deadline. It is not a verifier and cannot extend guest or external clocks.

## External protected selection and descriptor ownership

The separate fixed transport entrypoint must be explicitly selected. The existing `catchplate-native-shadow-verifier` no-arguments FD4/FD5/FD1 interface remains unchanged. Merely finding FD6 must never select transport mode.

Before opening any owned object, the transport entrypoint reserves the actual inherited sealed seed at FD4 and root-owned connected TCP socket at FD6, and requires FD5 to be absent. `PendingExchange::take()` owns only that exact FD6 and moves its retained descriptor above the child slots. It has no arbitrary FD constructor. The externally provisioned seed remains unread by Rust and must match the independent verifier authority through the unchanged Python verifier.

The supervisor opens its actual `RuntimeAdmission`, arms its original absolute `CLOCK_BOOTTIME` kernel watchdog, and only then calls `PendingExchange::receive(&admission, &watch)`. Receive occurs before image/root preparation, consumes the existing independently provisioned external window (at most 30 seconds), and cannot create a window from guest bytes or elapsed receive time.

The fixed public transport profile `/etc/catchplate/native-shadow-verifier-transport.json` is root:root 0400, singly linked, canonical ASCII, at most 16 KiB, with protected retained ancestors and no symlink traversal. Its exact5 fields pin the same actual held launch and verifier-policy originals and select one literal local address plus one literal peer IP. The full actual TCP local/peer tuple, peer ephemeral port, socket cookie/stat/flags, same-process PIDFD/start/boot/time namespace, and original external interval remain retained. The peer IP is a routing restriction, not an independent verifier or claimant identity.

The request cannot supply configuration, keys, PCRs, trust roots, nonce policy or deadlines. The pre-existing protected verifier policy must already select the exact expected statement, independent authorization/full18 keys, challenge, Nitro roots/PCRs/collateral and external boot/time window. The network original becomes a newly created final-verifier-UID/GID 0600, zero-link, four-seal memfd. `receive` returns `(Exchange, OwnedFd)`; the fixed parent must consume that actual file owner into `Inputs`, not overwrite whichever incidental object later occupies numeric FD5. The confined child still receives that genuine evidence at its source-fixed FD5 alongside retained config3 and seed4.

`Exchange::check(&watch)` preserves its originals and queued-data checks. `Exchange::publish(self, original, &watch)` only emits bounded canonical public bytes. The root-owned transport mode must invoke it **only** after the existing verifier child has passed retained-original/terminal checks, been reaped through the same actual PIDFD, its root retired, and its genuine exit status checked as zero. Neither exchange framing nor a caller-provided byte vector is a verification verdict. The guest repeats actual independent signature admission.

## Integration and evidence still required

This slice supplies the guest preparation/verification methods and private exchange owner, schema, and protected-original reuse. The separate [external transport entrypoint](native-shadow-verifier-transport-supervisor.md) now connects `run_transport`, the actual `Inputs` ownership join, terminal/reap-to-publish call and dedicated binary artifact in source. Independent socket/config/key provisioning and actual execution remain required. The native shadow launcher must independently select the post-C9 pin, retain and invoke the same key/closure/delivery owner; these modules do not create that launcher or the remaining receipt/proof endpoint servers, fixed-peer inspection, lifetime/settlement, independent authority or production readiness.

No build, parser/interpreter run, test, kernel/network execution, provider request or cloud action was performed for this source slice. Framing, partial I/O, parent EOF/drain behavior, original expiry, queued/trailing data, nonce/quote/signature rejection, cold provisioning, child terminal/reap failure and real Nitro acceptance remain required verification. The public transport intentionally makes no confidentiality or availability claim.
