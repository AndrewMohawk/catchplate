# Measured pre-subject capture retirement

This is an explicit, independently authorized **complete local provider retirement** profile for a retained initial OAuth token capture that never became a staged pending credential. It is not token-only cleanup, subject-specific retirement, Setup cancellation, refresh cleanup, or permission inherited from consent. Its possible impact on externally related provider grants is part of the signed authorization, not an implementation detail hidden from the grant issuer.

The actual source path is the native gate's `measured_capture_retirement` owner, the same retained measured secret broker, the dedicated native signing method, `POST /api/data-plane/oauth-capture-retirement`, the actual cold controlled-writer client, and the five `oauth.measured-capture-retirement.*` kernels. The explicit native startup selector is composed separately; older configurations and development paths do not acquire this purpose implicitly. The native configuration definition is `native-oauth-capture-retirement.v1.schema.json#/$defs/configuration`.

## Independent authority and exact originals

The signed measured authority configuration must contain `oauthMeasuredCaptureRetirementPolicy` and separately enable the fixed operations. Its distinct grant root admits a closed 35-field `catchplate.oauthMeasuredCaptureRetirementAuthorization/v1` payload. The root must differ from configuration, role, and other purpose roots. A current assignment independently binds the actual native holder, boot, key, role-4 NSM evidence, release/policy/configuration/CA/PCR/Eif scope, deployment, instance, application, encrypted client material, provider TLS roots, KEK identity and exact exchange IDs. Both the real verifier and planner admit the original signature and native attestation; a caller's fields or local TLS response do not establish measured authority.

The grant's `retirementScope` explicitly requires `complete-local-provider-retirement/v1`, the selected provider, all local applications and subjects, acknowledged external related-grant impact, and no automatic reopen. The fixed providers are Google and X. The grant authorizes one exact retained capture, not every token ever issued by that provider. Its original absolute action interval is at most 300 seconds. Each actual helper operation additionally retains a single at-most-30-second deadline, clipped by the original native lifetime and action grant; phase transitions do not renew it.

The writer consumes real `oauth_exchange_reservations`, source-selected `oauth_measured_exchange_custody` or `oauth_measured_setup_custody`, and `oauth_revocation_work` originals. It requires `retained`/`captured`/`held`, no staged pending original or later stage/cancel record, exact absent target pending/credential rows, exact prepare/claim/capture originals, original requester/application association, raw-response and minimal-issued ciphertext/hash equality, and a grant bound to these originals. The work sources remain `measured-oauth-exchange/v1` and `measured-oauth-setup-exchange/v1`.

For Setup, the exact independently bound session ID, initial row, started row and unchanged current row are retained and hash-bound. The original row must still be the actual revision-1 `oauth_started` association. Cleanup does not rewrite it to pretend pre-contact cancellation or completed Setup. Old consent/enrollment expiry is not renewed: the historical signed enrollment is authenticated under its grant-pinned historical root, while the distinct current cleanup grant supplies cleanup permission. A raw capture with no retained usable issued-token envelope cannot enter this effect path.

## Complete local scope and irreversible fencing

Inspection and claim acquire complete authenticated before-roots for credentials, pending credentials, exchange reservations and refresh reservations. Each table is currently capped at 32 rows and the grant at 16 affected active credential lineages. These are explicit temporary capacity limits, not filtered queries presented as completeness; over-capacity, unknown classification or incomplete roots refuse. The unchanged global query-proof ceiling remains 256; this operation's fixed query budget is 224.

The grant must name every actual local OAuth credential of that provider, including other applications and subjects. Each needs its exact current credential/generation head and a real strict currentness root. The actual control-plane coordinator quiesces and drains every frozen holder using the existing owner-bound acknowledgement path. Missing, old-profile, changed, already consumed or unresponsive roots refuse; timeout and cached-lease expiry are not acknowledgements. These drains cannot undo sends that already completed.

Other unresolved same-provider exchange or refresh contacts block retirement even if their deadlines expired. Prepared exchanges cannot cross the later provider fence; captured/staged exchanges and retained/committed refreshes do not count as unknown issuance contacts. Every pending row must be classifiable, but no provider subject is fabricated from a pre-subject token.

The claim transaction revalidates those exact complete roots and originals, consumes the admitted barriers, fences every affected credential as `revocation_pending`, installs permanent `oauth_provider_retirements`, and burns the selected work into the retirement journal. The provider-fence point read is joined to actual ordinary/measured exchange, Setup and activation, and refresh transitions. Reconnect adds the same fixed query and refusal through its separately owned kernel. Post-contact raw/issued capture is not blocked merely because the fence now exists: preserving already-produced evidence is not authority for another POST. Stage/activation/refresh commit and recovery paths that could produce use refuse after fencing. No general runtime DML grant is added.

## One contact per retained token identity

`inspect → claim → contact → finish` uses definite authenticated writer responses, not HTTP success alone. Only the actual helper opens the retained issued token, raw reply and encrypted application client material after the definite claim. It repeats the raw/minimal-issued derivation and exact application association before selecting tokens. Raw response AAD is the original exchange `response` artifact at version 1; minimal issued-material AAD is the original exchange UUID at version 1. No plaintext crosses the broker RPC, gate, control plane or database.

Google selects one actual refresh token, or access token if no refresh token was retained. X may select its actual access and refresh tokens, each under a separate stable exchange-plus-token-purpose attempt ID and definite pre-contact transaction. The helper performs fixed-provider HTTPS inside the measured process; the parent relay carries bounded TLS ciphertext only. It does not accept a caller URL or generic decryption/contact command. The grant must explicitly match the actual token-purpose selection.

Each `contact` burns its stable attempt before any provider byte. One local owner permits one attempt, and the protected attempt survives grants, boots and deadlines. `finish` retains the genuine helper-produced encrypted raw transport original and request commitment. States mean transport `accepted`, `rejected`, or `unknown`, never independently proven provider revocation. Without a complete transport original, the attempt stays `contact-claimed` and recovery reports `outcome-unknown`; no synthetic response is manufactured. A second X purpose is possible only after the preceding purpose has a definite retained accepted/rejected transport; unknown or lost receipt stops the chain. There is no inline retry, backoff, row deletion, fence reset or automatic reopen.

## Recovery and unfinished boundaries

`recover` is an observation-only operation under a separately current assignment explicitly naming the original authorization digest. It authenticates the historical grant/capture, exact retained claim/contact/finish originals, current database identity, fence and consumed barriers. It may report `no-local-claim`, `outcome-unknown`, `unknown`, `observed-accepted` or `observed-rejected`; none permits another provider POST. Absence of a local claim is not authority to restart a partially drained operation. Missing provider response or an uncertain finish cannot be repaired into success. Original encrypted captures, Setup history, grants and journals are preserved.

This finite source slice targets one capture while retiring a complete local provider. Other retained captures are not silently discharged. A provider already fenced by this v1 cannot receive another independent capture claim or reopen. Multi-capture succession, authenticated reopen/migration, larger populations, nondrainable legacy credentials and cross-deployment/provider-global coordination remain required follow-on work. Existing refresh, reconnect, Setup and ordinary/JIT requirements are not removed. Provider-wide local completeness does not prove an external account/project has no other grants.

Production still requires independently provisioned grant/configuration roots, current measured assignments and genuine native evidence, confidential application/KEK continuity for historical ciphertext, fixed TLS relay/root provisioning, installed protected schema/ACLs, and separately authorized end-to-end runtime acceptance. This source work runs no provider action, provisioning, build or test and supplies no runtime acceptance credit.
