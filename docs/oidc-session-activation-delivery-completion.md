# Consume completion and exact-outcome recovery

The dedicated completion library authenticates the actual consume originals,
reads an immutable commit through the real read-only owner, and signs a complete
control only after those two paths agree. This is not token release, permission
to execute again, or a claim that a cold completion service has been installed.
The current source is unbuilt, unexecuted and unprovisioned.

## Original-based completion

`authority_oidc_session_activation_delivery_completion._produce_from_custody_on_work`
accepts the original retained packet, its independently expected digest, original
caller authorization and caller/grant/state enrollments, independent historical
expectations, keys, configuration and pending database/generation/sequence/head/
fence. It requires the actual consume completion custodian and the actual fixed
commit reader. No successful candidate, incoming marker or unsigned SQL response
is accepted as proof.

The [dedicated packet decoder](oidc-session-activation-delivery-recovery-packet.md)
checks the independent identity before parsing the exact nine-field original
inventory. All four independently supplied enrollment/caller controls must equal
their retained originals. The genuine historical exchange authenticates the
caller, grant, encrypted private plan and consume effects once. Original reserve
and ACK signatures are checked against independent pending pins; the ACK cannot
supply those expected pins. The consume computation snapshot is reconstructed
from that same replay, including actual selected rows, mutations and full roots.

Only non-executable completion facts and an effects digest leave the private
admission suffix. Stored effects are compared to the genuine replay; they do not
become a supplied executable candidate. The fixed commit reader must return
normally after closing its database connection. Its marker and complete after
vector must exactly match the admitted originals before the enrolled completion
key signs a control containing the actual observation.

Historical execution intervals are data. They neither become a clock reading
nor extend old execution authority. One real current processing work/window and
absolute deadline covers custody, decoding, replay, read, signing and return.
Narrowing adds checks without discarding earlier sticky clock samples. Root and
signer pairs, actual owner identities and reader configuration remain bound.

## Durable recovery without re-execution

`authority_oidc_session_activation_delivery_completion_recovery.recover_and_deliver`
also requires actual configured packet/commit readers, the durable completion
delivery owner and the fixed state client. Their independently admitted database,
TLS/role/query/catalog and journal scope cannot be learned from a response.

The first call reads the actual retained packet and follows genuine original
admission and commit observation. It retains the first exact signed completion
before any state delivery. Subsequent calls recover that immutable original;
they authenticate its signature, identity and complete marker bindings rather
than sign a replacement. A genuine state lookup can recover an already retained
ACK or establish that only unchanged original redelivery is permitted. Changed
or ambiguous state does not mean SQL failed and does not clear an attempt.

The recovery branch also joins retained caller authorization and all enrollment
originals to independently supplied bytes. The result contains only the exact
durably retained ACK and its request identity. It is not a fresh permission,
current-session assertion, browser token or plaintext release.

## Remaining integration

These are source library components inside token-release row 14, not that row's
completion. Dedicated cold signing/readers/TLS/journal resource delivery,
completion-purpose state routing, actual startup/service and private response
admission remain to be connected. Generic original replay/grant/recovery entry
points remain closed to consume. Exact committed-original token release and its
cold response/handoff remain separate later rows; production acceptance still
requires immutable release evidence and independently provisioned services.
