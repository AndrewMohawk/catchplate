# Consume-only execution-authorizer delegation

The `.161` source adds a distinct root-signed enrollment for the future private
`oidc.session.activation-delivery.consume` grant authorizer. This is a delegation
contract and real original-byte producer/verifier, not grant issuance, current
caller permission, protected execution or an installed authorizer service.

The closed payload fixes one `operation`, not a caller-selected operation array.
Its signature and original-byte identity domains differ from the generic
successor enrollment. An old generic delegation cannot be relabeled as consume
authority, and the generic seven-family execution path does not admit this new
enrollment. The separate [replay-family boundary](authority-successor-replay-families.md)
keeps consume planning registration from enabling incomplete execution replay.

Both production and verification genuinely admit the independent original
current-root enrollment. Database, generation and current-root identity are
derived from that admission, not a caller's successful result or storage data.
Canonical authorizer PEM/SPKI and independent measurement, source-bounded age
and skew are signed. The actual authorizer key must differ from root,
computation, completion and state keys. Caller/planner key separation is checked
again by the [consume caller authorization](oidc-session-activation-delivery-execution-authorization.md).

The exact envelope is capped at 16 KiB. Decode, capture, canonical comparison,
key/signature operations and output reservation share the supplied work ledger.
The producer holds immutable originals, scalars and key references before native
callbacks, signs only its fixed enrollment domain and genuinely re-admits its
original signed result. It creates no key, clock window, new work allowance,
database record, filesystem object or public API.

Root signing authority and enrollment policy must already be independently
admitted. This module does not operate the root service or prove that the
enrolled key is in hardware. Unknown source/configuration cohorts still require
explicit enrollment rather than compatibility fallbacks.

The [encrypted original codec](oidc-session-activation-delivery-execution-bundle.md)
and caller control bind a portable plan/ciphertext pair, but first-exact export,
independent consume receiving custody, genuine full original replay before
grant signing, cold key delivery/service and issuance integration remain open.
Reservation, SQL, completion/recovery, plaintext release and public/portal
permission remain separate. Source is unbuilt and unexecuted; no production
gate closes and no new authority was provisioned.
