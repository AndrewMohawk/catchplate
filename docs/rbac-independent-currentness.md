# Independent RBAC currentness

This source connects the actual `rbac.binding.mutate` controlled writer and authoritative RBAC readers to a separately enrolled PostgreSQL witness. It is source-only, unbuilt, unexecuted and unprovisioned. A second schema, table, local ledger, or database on the metadata rollback domain is not an independent witness.

## Actual chain and root recipe

The existing controlled-authority HTTP ingress, genuine WebAuthn verification and signed planner still authorize the role change. The disabled legacy RBAC PUT/deprovision endpoints remain disabled. No witness head, TLS certificate or receipt substitutes for the existing actor/assertion policy.

`authority_transition_policy._RbacBindingMutateKernel` now derives the actual next `rbac_role_bindings` root using the admitted selected originals, primary proofs and existing root-transition engine. Both writer and `db.py` reader use `rbacAuthenticatedState/v1`: generation, binding-root revision/digest/leaf count and the source query-manifest digest, serialized as canonical Python ASCII JSON. The former delta-only writer digest is not relabeled as this state. The v9 executor brackets this specific verified RBAC mutation with the existing revision-owner GUC; its explicitly planned authority revision is not incremented again by the legacy trigger. Reset/empty GUC means no revision owner.

The external head commits both the `rbac_authority_state` and `rbac_role_bindings` roots, generation and that state digest. Stable `databaseId` is SHA-256 of `serverware/rbac-metadata-identity/v1\0` followed by canonical `{clusterId,database}`. Changing a deployment or enrollment label cannot create a new slot for the same metadata database.

The actual verifier admits the genuine signed plan, reads the independent head, then reserves an exact nine-field intent before issuing the executor capability. Reserve compares the original predecessor, increments sequence/generation exactly once and stores the exact original. It does not hold a metadata lock or call a metadata writer while upgrading a shared witness read lock.

The actual executor holds a witness row SHARE lock through the metadata transaction's definite commit. It compares the actual metadata cluster/database and both maintained roots; an RBAC mutation additionally requires its exact pending request/capability and expected after-state. Other operations reading RBAC require a nonpending head. A new reservation cannot cross this execution bracket. The verifier completes the external head only after its existing exact executor receipt/result/root checks returned. The old generic replay witness remains separate and unchanged.

`db.get_rbac_authority_state`, generation/binding reads and transaction-bound role checks compare the fresh external head. OIDC bearer/session role refresh already reaches those functions. The real planner root-acquisition boundary checks every consulted RBAC root, including its shared private read paths; no caller-supplied root becomes currentness. Primary proofs still authenticate selected rows. These checks are not a retroactive cancellation of effects already authorized at an earlier linearization point.

## Cold authority and independent deployment

`control_plane_rbac_currentness.initialize_from_environment()` runs after genuine CP custody admission and before the HTTP runtime. Actual verifier/planner/executor construction calls `initialize_authority(self)` after its genuine role launch and attestation admission. The owner retains original sealed descriptors, process identity, actual custody/configuration binding and original expiry. There is no lazy admission or authority callback. Only unconfigured development opts out; configured, failed, closed, expired or changed production state refuses.

The eight-field `serverware.rbacWitnessStartup/v1` selects `root`, `enrollment`, `tlsRoot`, `clientCertificate` and `clientKey` alongside source/configuration identity. Four original references are exact `{fd,sha256}`; no arbitrary source path is accepted. The root is separately pinned and must differ from the admitted runtime/configuration root. The independently signed enrollment fixes the real metadata and witness cluster IDs and distinct fault-domain identities, the endpoint, TLS CA/certificate originals, reader/writer identities, initial roots/state, current configuration digests, original validity and record quota. Code verifies actual cluster IDs; independent fault-domain administration still requires external provisioning evidence, not different strings alone.

The CP fixed delivery paths are `/run/serverware/authority-trust/rbac-witness.json`, `rbac-witness-root-public-key`, `rbac-witness-tls-root`, `rbac-witness-reader-certificate`, plus `/run/secrets/serverware-rbac-witness-reader-key`. Verifier/planner/executor use the matching fixed systemd credential names in `authority_fd_entrypoint.ROLE_SOURCES`; all five descriptor names are also required by the signed launcher inventory. The private key must be root-owned sealed mode `0400`. No HTTP request supplies connection material.

Libpq connects once per bounded scope with the pinned address/hostname, TLS 1.3 `verify-full`, retained TLS FDs, and exact independently enrolled reader or writer role. The actual server cluster/database, TLS client DN/serial/issuer and role privilege closure are checked. The CP, planner and executor are read-only witness consumers; only the actual verifier receives witness write material. The metadata role gains only read-only `pg_control_system()` inspection, not runtime DML. SQL/schema ownership and witness client-certificate authentication must be provisioned independently before use.

`authority_rbac_currentness.sign_enrollment` is the offline signed-original producer; no runtime owns that key. `authority_rbac_witness.provision` is an explicit initial operator action on the separately selected witness cluster, not HTTP/runtime bootstrap. It requires its own idle actual Psycopg connection with `dict_row`, owns the transaction, and refuses any existing namespace, including uncertain prior initialization. It never adopts the metadata database's observed state, resets a head, changes an existing namespace, or migrates a legacy delta digest. The initial state must already match independently selected originals and this source recipe. Provisioning and runtime connections require `fsync` and `full_page_writes` enabled and select local synchronous commit. `authority_store/rbac_witness_sql.py` installs fixed SECURITY DEFINER read/reserve/complete procedures with fixed `pg_catalog` search paths and EXECUTE-only client privileges; there is no path/table-selected SQL. Runtime clients refuse role membership, database ownership, schema/database creation, temporary-table rights and direct witness-table privileges.

## Exact originals, uncertainty and limits

The paired [schema](../schemas/rbac-witness.v1.schema.json) is data-only. Enrollment is at most 64 KiB, startup 96 KiB, a head 16 KiB and each intent/completion 8 MiB. At most 4,096 intent records are admitted. Intent originals are immutable; each admits at most one exact completion original. Completion retains the genuine writer receipt and canonical result bytes in base64url, with their distinct byte hashes. The stored pending digest and head change in the actual witness transaction. No caller `ok`, local SQL history, old replay-witness status or timeout is completion evidence.

Lost reserve acknowledgment means no executor permission is returned. Lost metadata/external-completion acknowledgment or an expired original leaves uncertainty; a pending head refuses authorization and further RBAC mutations. The code never infers noncommit from the old state, expires a pending record, clears an intent, automatically retries, re-signs a request, or rebuilds an original. An exact already-completed procedure lookup is data-only and never reenters metadata effects. A newly admitted process using the same original enrollment keeps the same external namespace and compares its actual head; process restart is not enrollment or sequence reset.

All operation scopes are at most 30 seconds and clipped to original caller/custody/attestation/enrollment bounds. Enrollment validity is source-capped at 24 hours. The additive [v2 known-commit recovery](rbac-known-commit-recovery.md) connects a fresh recovery-only verifier to exact protected committed originals and independent witness completion; v1 remains current-only. Exhaustion, ordinary expiry, unsupported historical sources, source/configuration handover, certificate/root rotation, cluster transfer, legacy-root migration and unresolved outcomes lacking positive commit evidence still require separately authorized lifecycle successors. These remain real follow-on requirements, not permanent product exclusions or claimed production completion.

Acceptance requires an independently administered witness and genuine TLS/role credentials, plus authorized integration checks of both commits, rollback refusal, pending uncertainty, concurrent readers/writers and restart continuity. No such runtime acceptance or deployment is claimed here. Simultaneous rollback of both trust domains or compromise of their independent provisioning authority is outside this witness's guarantee. WebAuthn public revocation/current-root authority is neither replaced nor aliased.
