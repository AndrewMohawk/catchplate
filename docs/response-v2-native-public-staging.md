# Native public Reserve, Authorize and Stage

The selected path connects the actual gate transaction to the actual StateAuthority, PolicyProofVerifier and ImmutableArtifactLedger. It does not infer a staged attempt from a public success object. The gate's retained authenticated Hello/session, actual PIDFD/process/cgroup originals, original millisecond-aligned deadline and credential-free input descriptors remain bound throughout.

## Explicit selection and independent admission

The nested `serverware.nativeResponseObservationV2Config/v3` client requires the existing guest listener and `nativeStaging: {"apiVersion":"serverware.responseV2.nativeStaging/v1"}`. It is admitted only from the actual cold Pending encrypted-service-token source and outer startup v14/v15 with the actual gate-cgroup producer. Before serving, startup binds that retained owner to the genuine serving identity and original lifetime. Nested v1/v2 and environment profiles do not acquire this capability; outer v1–v13 refuse it. The v14 schema explicitly retains the older nested alternatives alongside v3, and v15 inherits that choice. No new outer startup version is introduced here.

The separately signed guest configuration must assign `nativeStaging` using `serverware.responseV2.nativeStagingAssignment/v1`, purpose `native-gate-reserve-authorize-stage-v1`. Its exact field schema is [`configuration`](../schemas/response-v2-native-staging.v1.schema.json#/$defs/configuration); absence keeps old profiles and explicit null refuses. The receiver independently verifies the original role-4 Nitro document, certificate chain, PCR/EIF/module, native boot/key, release/configuration/CA/policy/binary scope and dedicated staging nonce/signature. Existing target-dispatch admission is also required but cannot substitute for this staging purpose. A configured string, local UDS hello or caller verdict is not measured evidence.

The actual gate captures its own retained PIDFD and process-start original. `ProcessOwner` carries process ID, PID, start ticks, concrete relative cgroup ID and the process/raw-cgroup hashes. The supervisor compares the hashes with the genuine per-packet guest inspector and the actual authenticated sender/session. The dedicated gate cgroup producer creates `serverware-native-gate` before role startup and moves only the gate after child creation, before the permanent privilege drop. Its `/proc/self/cgroup` original is `0::/serverware-native-gate\n`; the hash is not a pathname. Old inherited-root configurations cannot satisfy this path. Provisioning and runtime confirmation of this independent assignment remain external prerequisites.

## Fresh state profile, not historical migration

`postgres::native_staging_profile::bootstrap_sql()` selects the fresh-only `native-staging-originals/v3` schema and exact migration digest. It extends the explicit sequence/original v2 schema; schema metadata version is 3. The actual generation pin, constructor and locked database metadata must agree before a claim. Existing populated databases, old hash fences and legacy rows are not rewritten, truncated, reinterpreted or backfilled. Historical migration remains required follow-on work.

Reserve uses the real database allocation sequence and a canonical positive decimal fence. Zero revision/fence exists only in the pre-allocation intent. The old execution wrapper is not broadened to permit an unallocated Reserve. Full signed frames and committed results remain distinct from bare unsigned request hashes.

Two new protected append-only relations retain the public phase claim and its completed signed terminal. A claim records exact admitted native request, session, and bounded metadata originals. No final injected request or plaintext credential is stored. The terminal records the actual positive signed state operations; completion rechecks their exact protected operation and replay rows, current attempt/owner/fence and original deadline in the same transaction.

## Real effect ordering

For each public phase, the state owner first inserts and definitely commits its one-shot claim. It never holds that transaction while calling another role. A claim without a known completed result is uncertainty and cannot repeat a policy call, publication or SQL transition. Exact already-completed originals may be returned without effects while their original authority remains valid; this is not an expiry extension or an automatic retry loop.

- Reserve signs its source-owned allocation frame and commits the actual Reserved attempt with exact request, route, credential scope, PID/start/cgroup and deadline.
- Authorize supplies the independently keyed policy role with the state-signed durable claim, original Reserve envelope/result, and five sealed metadata descriptors. The policy role checks the admitted exact gate evaluation, route/session, actual credential version and release/JIT reservation semantics, then signs an `AttemptAuthorize` transition artifact. The state owner commits that actual artifact. It does not claim that release dispatch has occurred.
- Stage binds the exact prior Authorize terminal and source-owned injection template/credential commitment. The independently keyed ledger consumes its fresh publication slot, persists and fsyncs the exact credential-free HTTP object and receipt, and returns a genuine signed `ObjectCommitRaw` frame. It does **not** synchronously call back into the state owner. StateAuthority commits that frame locally, then executes the closed companion-original Stage method.

The legacy `AttemptStage` artifact contract is unchanged: an Authorize artifact is not relabelled as Stage permission. The new companion method verifies the original Authorize frame/result against the protected successful operation/replay and preceding public journal terminal, the exact AUTHORIZED predecessor, then exact object publication, session, owner, revision, fence, deadline and artifact equality in the same Stage transaction.

ObjectCommitRaw and Stage are two real commits and increase the revision twice. The internal object commit uses its fixed `staged-put:<original-hash>` request/operation ID; Stage retains the public request ID, so they never collide in the generation-wide replay ledger. The selected gate cursor accepts this only after verifying the state-signed terminal and both full committed originals. The old single-step cursor is unchanged. The stored object keeps its actual source descriptor ID and is `staged-request` / `http11-request`; it is not the later injected HTTP request. The existing native target-dispatch owner independently retrieves the exact Stage witness before its sole DispatchBegin and retains its separate gate-owned final request hash.

The concrete successor join uses `dispatch:<original-hash>` as the real DispatchBegin operation ID and its genuinely signed CredentialUse artifact's operation/artifact ID. Both the role receiver and gate check this same derived ID. The state store's exact operation-ID and signature checks remain unchanged; the previous unrelated `use-artifact:` producer spelling could not satisfy that store contract.

## Transport and bounds

`responseObservationV2.nativeStaging/v1` carries the ordinary response-data outer version/request ID/boot plus exact parameters `{binding, stableResumeId, request}`. The duplicate wrapper binding must exactly equal the independently admitted native original and real session. Its result is `SignedStagingResult` with the public phase result and one or two exact committed originals; an outer transport acknowledgement alone is insufficient.

Native originals use dedicated `serverware.nativeStagingStatement/v1` signature and `serverware/native-staging-attestation/v1` quote domains. Role claim/result/storage signatures keep their explicit separate domains and existing canonical UTF-8 recipe; native statements use canonical ASCII. No old signing family is widened.

The source-selected service descriptor inventory is Reserve 3, Authorize 2 and Stage 2 at StateAuthority; policy receives exactly five; staged storage receives exactly one credential-free HTTP descriptor. Legacy descriptor APIs remain capped at one. Inputs must retain actual immutable memfd seals and exact bytes. Metadata objects are capped at 64 KiB each, aggregate retained metadata at 256 KiB, staged HTTP at 16 MiB, native statement at 48 KiB, native request/terminal at 192 KiB, and each signed state frame/result at 24 KiB. The existing signed service frame bound remains exactly 256 KiB. Aggregate overflow refuses before the affected call; no splitting is allowed.

## Uncertainty and remaining boundaries

Malformed, partial or unknown journal/CAS state is retained, never repaired, deleted or adopted. Ledger partial output remains evidence; no automatic replacement or file retry is available. The gate does not reopen, re-sign or enter the old Reserve retry path after an uncertain new-profile operation. No timeout proves nonexecution. A future independently authorized recovery/migration owner is needed for unresolved public claims; this slice does not manufacture one.

This profile requires an actual credentialed decision. Ordinary credentialless forwarding remains on its existing separate optional-credential path; this does not add a request-only response-v2 proof family or waive that path's policy/JIT controls. Historical migration, broader setup/reconnect, provider authorship, cross-deployment authority and deployment/runtime acceptance remain open. The actual cgroup owner is source-connected; independent assignments, signed profile provisioning and explicit acceptance remain necessary before a pilot.
