# Trusted-host-local measured roster

`scripts/authority/local_closure.py --help` describes the fixed public FD/hash
and protected signing-key inputs. This is an actual measurement/signing path,
not a producer of native `CompleteClosure/v1` evidence.

The independent approval selects an already frozen file tree, explicit Python
import rows, native executable/object rows and the local Python bootstrap.
The issuer authenticates the existing snapshot receipt and its authorized key,
remeasures the entire tree, joins every selected row to measured bytes, and
reads bounded x86_64 ELF metadata. `PT_INTERP`, `DT_NEEDED` names and `DT_SONAME`
are checked against the selected native inventory. This checks the declared
dependency-name association, not the dynamic loader's future resolution.

Only after those checks does it read the independently supplied
`closure-verifier` key and sign
`serverware.authorityTrustedHostLocalMeasuredRosterReceipt/v1` under a distinct
signature domain. The receipt remains detached from the tree it measures. Its
assurance is explicitly `measured-roster-at-issuance`:

- Python rows bind selected bytes, not exhaustive static/dynamic import analysis.
- Native rows bind selected bytes and ELF metadata, not future `dlopen`, NSS,
  plugin, IFUNC, HWCAP, audit or search-path behavior.
- Rootfs isolation, pivot/old-root detachment and hardware custody are not proven.

The artifact generator and package verifier accept this receipt only with the
explicit trusted-host-local Python bootstrap. The local verification receipt
uses `complete=false` and the same explicit assurance. Native/external/TEE
profiles retain the original complete-closure schema, coverage, signature domain
and `complete=true` requirements.

No source tree, signing key, trust ledger or receipt prerequisite is generated by
this command. Output requires complete pipe bytes and successful exit within the
original dual-clock window. There is no retry or trust-state advancement.

The isolated guest's successful verity/immutable/no-replace probes establish
storage capability only. A real pilot still needs the actual assembled signed
package installed by the local installer in that guest, independently supplied
role credentials and late admission originals, and observed application behavior.
Neither these source changes nor a signed roster receipt establish that deployment.
