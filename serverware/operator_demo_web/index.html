Access rules

Allow an application to use one saved credential at one exact path. Reuse either resource in more rules without submitting the provider secret again.

Header from the saved credential: (cannot be overridden here).

Enter the full value only, not the header name. For Authorization, include the Bearer prefix if your client sends it, for example Bearer SERVERWARE_DUMMY. Case and spaces must match exactly; no leading or trailing spaces. This is public rule configuration: never enter a real provider secret or your Serverware application token. Replacement applies only to this rule, not other requests using the saved credential.

Destinations are deployment-managed. One exact path beginning with /. No wildcard, query string or fragment.

Proxy setup

Connect your existing HTTP client through Serverware using the proxy address, public CA and an application token. The console URL is not the forward proxy.

Use your existing client's proxy settings

Keep your client's API URL, method and request data. Configure its HTTPS proxy endpoint below, send the application token as proxy authentication, and trust the downloaded CA for the destination inside the tunnel. Your client must support these proxy and TLS settings.

Every request must still match an active access rule. Follow that rule's credential-input choice: send no provider credential header for automatic insertion, or exactly the configured dummy value for replacement.
